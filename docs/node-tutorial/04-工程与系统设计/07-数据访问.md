# 数据访问

示例：`examples/B/13-sqlite.mjs`。API 细节见 [SQLite](../02-进阶/13-SQLite.md)。

数据访问层只做一件事：把领域操作变成具体的读写。路由不拼接 SQL。

查询参数用占位符。示例把 `ada' OR '1'='1` 作为参数传入，匹配行数是 0。把这段文本拼进 SQL 字符串会改变语句结构。

多条写入放在 `BEGIN` / `COMMIT` 里。中途失败就 `ROLLBACK`，避免留下一半数据。

`node:sqlite` 的 `DatabaseSync` 在 22.23.4 是同步 API，并且仍打印 ExperimentalWarning。大查询会占住主线程。请求路径上的大库要换异步驱动，或把同步调用放进 Worker，并接受序列化成本。

行对象的原型是 `null`。业务代码读取字段即可，不要假设它是普通对象，也不要把它递归合并进别的对象。

连接或文件句柄在 `finally` 里关闭。进程退出见 [优雅退出](./10-优雅退出.md)。


## 是什么

数据访问层把领域操作变成具体的读写。路由不拼接 SQL。参数用占位符。多条写入放在一个事务里，失败就回滚。

`node:sqlite` 的细节和实验警告见[SQLite](../02-进阶/13-SQLite.md)。行对象原型是 `null`。同步 API 不适合放在繁忙的请求路径上。

## 事务的边界

事务要短。不要在事务里等 HTTP 或用户。连接在事务结束前不要还到池里给别人用。`finally` 里提交或回滚，然后释放连接。进程退出见[优雅退出](./10-优雅退出.md)。

迁移是另一条路径：启动时用版本号决定要不要改表，不要在每个请求里 `CREATE TABLE IF NOT EXISTS` 顺便改列。

## 本章问答

### 1. 拼接 SQL 和占位符差在哪？

**考点：** 语法和值。

**回答：** 占位符的值不会变成语法。示例把 `ada' OR '1'='1` 当参数，匹配行数是 0。拼接会让引号结束原来的字符串。转义规则跟数据库走，不要手写。

### 2. 事务里为什么不能发 HTTP？

**考点：** 占用时间。

**回答：** 事务持有锁。等 HTTP 的几秒里，其他写入都堵着。先在事务外拿到需要的数据，事务里只做本地读写。

### 3. 为什么不要每个请求建表？

**考点：** 迁移和请求路径。

**回答：** 建表和改列是部署步骤，有版本、有失败处理。放进请求里会在并发下互相打架，也会把实验性的同步调用加到热路径上。

## 事故复盘

事务里 `await fetch(webhook)`。锁持有数秒，其他写入排队，数据库连接耗尽。事务里只做本地读写。

每个请求 `CREATE TABLE IF NOT EXISTS` 并顺便加列。并发迁移互相打架。改表是部署步骤，有版本号。

拼接 SQL 被一段 `OR '1'='1` 打穿。占位符下这只是一个不匹配的字符串。
