# 安全

示例：`examples/D/08-safe-path.mjs`。路径规则的入门版见 [进程与路径](../01-入门/08-进程与路径.md)。

把用户输入拼进文件路径之前，先归一化再判断是否仍在根目录里：

```javascript
const resolved = path.resolve(root, userPath);
const relative = path.relative(path.resolve(root), resolved);
```

相对路径以 `..` 开头，或变成绝对路径，就拒绝，示例用 `E_PATH_ESCAPE`。`a/../b.txt` 仍在根内，允许。`../secret`、`/etc/passwd`、`a/../../secret` 拒绝。

这是字符串层面的检查。根目录里如果有指向外部的符号链接，打开文件后还要用真实路径再查一次。

同一类边界：

- SQL 用占位符，见 [数据访问](./07-数据访问.md)。
- 子进程参数用数组，不要开 `shell: true`，见 [子进程](../02-进阶/09-子进程.md)。
- JWT 钉死算法，见 [会话与 JWT](./06-会话与JWT.md)。
- 摘要比较用 `timingSafeEqual`，长度不同要先判断。
- 合并 JSON 时跳过 `__proto__`、`prototype`、`constructor`。`JSON.parse` 本身在 22.23.4 上不会改原型，见 [集合与 JSON](../01-入门/04-集合与JSON.md)。
- 权限模型限制进程能读哪些文件，见 [权限与类型剥离](../03-运行时/14-权限与类型剥离.md)。它不代替登录鉴权。

错误响应只给调用方能处理的代码和简短说明。


## 是什么

安全边界就是所有从进程外进来的字节：路径、SQL、命令行、JSON、令牌、转发头。每一处都有对应的示例，而不是一句「注意安全」。

## 本章问答

### 1. 只搜索 .. 为什么不够？

**考点：** 绝对路径和合法的 `..`。

**回答：** `a/../b.txt` 仍在根内，不该拒绝。`/etc/passwd` 里没有 `..`，但 `resolve` 会把它当成绝对路径，根目录消失。用 `path.relative` 的结果判断。符号链接还要再查真实路径。

### 2. JSON.parse 和原型污染是什么关系？

**考点：** 22.23.4 的实际行为。

**回答：** `parse` 得到自有属性 `"__proto__"`，不会把 `admin` 放到原型上。污染发生在随后的递归合并。跳过那三个键，或用 `Object.create(null)`。

### 3. 权限模型和登录是什么关系？

**考点：** 两层。

**回答：** `--permission` 限制进程。登录限制用户。没有 `--permission` 时 `process.permission` 是 `undefined`，文件照样能读。用户身份仍要在应用里检查。

## 事故复盘

只判断路径字符串包含 `..`。合法的 `a/../b.txt` 被拒绝，绝对路径 `/etc/passwd` 被放行。用 `path.relative` 的结果。符号链接再用真实路径查一次。

合并 JSON 时没跳过 `__proto__`。`JSON.parse` 在 22.23.4 不会改原型，合并函数会。

错误响应带了堆栈和 SQL。调用方获得了表结构。正文只留错误码。
