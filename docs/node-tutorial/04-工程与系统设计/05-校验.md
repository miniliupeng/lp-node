# 校验

示例：`examples/D/06-validation.mjs`。

外部输入包括 HTTP 正文、查询字符串、文件内容和消息队列里的 payload。校验放在边界，失败就抛错或返回 400，不要让坏数据进入领域函数。

示例只接受普通对象，并且只取出 `name` 和 `age`：

- `null`、数组都拒绝
- `name` 必须是长度 1 到 40 的字符串
- `age` 必须是 0 到 130 的整数。字符串 `"36"` 拒绝
- 多余字段 `extra` 被丢掉，返回值只有 `{ name, age }`

这叫白名单。把用户对象原样展开进数据库，会把调用方塞进来的 `role` 或 `isAdmin` 一起写进去。

数字用 `Number.isInteger`，不要用 `typeof x === 'number'`，因为 `NaN` 和 `Infinity` 的 `typeof` 也是 `'number'`。

错误信息可以说明哪一个字段不合法。不要把内部 SQL 或堆栈返回给客户端。


## 是什么

外部输入包括 HTTP 正文、查询、文件和队列消息。校验在边界做，失败就 400。领域层不再重复猜测类型。

示例 `examples/D/06-validation.mjs` 只接受普通对象，只留下 `name` 和 `age`。`null` 和数组拒绝。`name` 长度 1 到 40。`age` 必须是 0 到 130 的整数，字符串 `"36"` 拒绝。多余字段丢掉。

## 类型收窄和运行时是两层

TypeScript 的收窄只存在于编译期。`node file.ts` 把类型擦掉，运行时仍要自己检查。见[类型收窄](../01-入门/14-类型收窄.md)。`typeof x === 'number'` 挡不住 `NaN` 和 `Infinity`。整数用 `Number.isInteger` 加范围。

白名单比黑名单安全。`{ ...input }` 会把 `isAdmin` 一起带进数据库。错误信息可以指出字段，不要带 SQL 或堆栈。

可辨识联合在运行时就是一个标签字段加 `switch`。漏掉的 `kind` 要走到 `default` 并抛错。示例 `examples/A/14-guards.mjs` 对未知 `kind` 抛 `TypeError`。

## 本章问答

### 1. 为什么 age: "36" 不能通过？

**考点：** 字符串和整数。

**回答：** JSON 里的数字和数字字符串不是一回事。接口若声明整数，字符串应 400，而不是偷偷 `Number()`。偷偷转换会把 `"36abc"` 收成 `NaN` 或截断，取决于你怎么写。

### 2. 多余字段为什么要丢掉？

**考点：** 批量赋值。

**回答：** 调用方可以塞 `role` 或 `isAdmin`。展开进数据库就会写进去。返回值只含你点名的字段。

### 3. TypeScript 接口能不能代替运行时校验？

**考点：** 擦除。

**回答：** 不能。类型在运行时不存在。外部 JSON 是 `unknown`，要用和示例一样的检查。`tsc` 负责你自己的代码，不负责网络上送来的字节。

## 事故复盘

`const row = { ...req.body }` 写进用户表。调用方带了 `isAdmin: true`，成为管理员。白名单只留 `name` 和 `age`。示例丢掉 `extra`。

`age: "36"` 被 `Number` 收成 36，另一个调用方传 `"36abc"` 变成 `NaN`，最后写成 0 岁。整数用 `Number.isInteger`，字符串年龄直接 400。

TypeScript 接口被当成运行时校验。剥离之后什么都不检查。外部 JSON 从 `unknown` 开始查。
