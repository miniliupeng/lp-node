# 会话与 JWT

示例：`examples/D/02-jwt.mjs`。HMAC 见 [密码学](../02-进阶/10-密码学.md)。

示例实现的是教学用 HS256，不是完整的 JWT 库。它做了这些事：

1. 头和载荷用 JSON，再 base64url。
2. 签名是 `HMAC-SHA256(secret, header + '.' + payload)`。
3. 校验时只接受 `alg === 'HS256'`。`none` 或其他算法直接失败。
4. 签名比较前先看长度，再用 `timingSafeEqual`。
5. `exp` 是秒。`nowSeconds >= exp` 则过期。

签名不是加密。任何人都能解开载荷。不要把密码放进载荷。

调用方可以改头里的 `alg`。如果实现按头来选择算法，就可能被换成 `none` 或换到另一把公钥。示例把算法钉死在 HS256。

密钥要有足够熵，放在环境里，定期轮换时要能同时接受旧密钥一小段时间。示例的 `test-secret` 只用于断言。

服务端会话把随机 id 放进 cookie，状态放在服务端。JWT 把状态放在令牌里，撤销要额外的黑名单或很短的过期时间。选哪一种，取决于你要不要即时撤销。


## 是什么

会话把随机 id 放进 cookie，状态放在服务端。JWT 把声明放进令牌，服务端用密钥验证签名。示例 `examples/D/02-jwt.mjs` 是教学用 HS256：base64url、钉死 `alg === 'HS256'`、长度检查后再 `timingSafeEqual`、`exp` 按秒比较。签名不是加密。

## Cookie 的三个属性

| 属性 | 作用 |
| --- | --- |
| `HttpOnly` | 脚本读不到这条 cookie，减轻 XSS 把会话偷走的后果 |
| `Secure` | 只在 HTTPS 上发送 |
| `SameSite` | 限制跨站请求是否带上 cookie。`Lax` 是当前浏览器常见默认：跨站的普通 POST 不带，顶层 GET 导航可以带。`Strict` 更紧。`None` 必须同时 `Secure` |

这些属性防的是浏览器怎么发送 cookie，不防服务端自己把令牌打进日志。

## 怎么选

要立刻作废登录，用服务端会话，删掉存储里的 id。JWT 在过期前仍然有效，除非另做黑名单，而黑名单又把状态带回来了。短过期加刷新令牌是折中。移动端和跨服务调用常用 JWT。管理后台常用会话。

密钥要有足够熵。示例的 `test-secret` 只用于断言。轮换时要有一段时间同时接受旧密钥。

## 本章问答

### 1. 为什么不能信任头里的 alg？

**考点：** 算法混淆。

**回答：** 调用方可以改头。按头选算法时可能被换成 `none`，或换到另一把密钥。实现只接受 HS256。其他值失败。不要先解析头再按 `alg` 分支。

### 2. HttpOnly 防的是什么，不防什么？

**考点：** XSS 和 CSRF 不是同一个问题。

**回答：** `HttpOnly` 让 `document.cookie` 读不到会话。它不阻止攻击者利用已经登录的浏览器去发请求。跨站请求靠 `SameSite`、CSRF 令牌和正确的方法。`Secure` 防止明文 HTTP 把 cookie 发出去。

### 3. JWT 为什么难注销？

**考点：** 无状态的代价。

**回答：** 任何持有密钥的节点都能验签，服务器不记得签发过谁。要立刻踢人，就要共享的黑名单或很短的过期时间。黑名单失效时，你又回到了会话的可用性要求。

## 事故复盘

验签按头里的 `alg` 分支，攻击者改成 `none`，没有签名也通过。实现只接受 `HS256`。示例对其他算法失败。

JWT 当会话用，用户点了退出，令牌在过期前仍能用。要立刻作废就用服务端会话，或接受黑名单的代价。

Cookie 没设 `HttpOnly`，XSS 脚本读到会话。`HttpOnly` 不防 CSRF。跨站是否带 cookie 看 `SameSite`。
