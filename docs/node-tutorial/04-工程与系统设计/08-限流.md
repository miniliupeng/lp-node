# 限流

示例：`examples/D/01-token-bucket.mjs`。

令牌桶有容量和补充速率。请求到来时尝试取走一个令牌。没有令牌就拒绝，通常回 429。

示例容量 2，每秒补充 1 个。时间由调用方传入，所以测试不用真的睡觉：

| 时刻 ms | 结果 |
| --- | --- |
| 0 | 成功，剩 1 |
| 0 | 成功，剩 0 |
| 0 | 失败 |
| 999 | 失败，还没补满 1 个 |
| 1000 | 成功 |
| 1000 | 失败 |

进程内的桶只限制这一个进程。`cluster` 或多次部署时，每个进程各有一份计数，总限额会变成「进程数 × 限额」。要全局限额，把计数放到所有实例都能原子更新的存储里。

限流键可以是用户 id、令牌或 IP。直接信任 `X-Forwarded-For` 会被伪造。只采用你自己的反向代理写上的那一跳。

拒绝时写 `Retry-After`，并避免在失败路径上做重活。


## 是什么

令牌桶有容量和补充速率。请求取走一个令牌，没有就拒绝，通常回 429，并写 `Retry-After`。

示例容量 2、每秒补充 1 个。时间由调用方传入：0ms 成功两次，第三次失败；999ms 仍失败；1000ms 成功一次。

## 进程内计数的范围

`cluster` 或多次部署时，每个进程各有一份桶。总限额变成进程数乘以单进程限额。全局限额要把计数放到大家都能原子更新的存储里。固定窗口在边界上会放进将近两倍的流量，讲方案时要说清窗口怎么切。

限流键可以是用户 id 或令牌。IP 只采用你自己的代理写上的那一跳。直接信任 `X-Forwarded-For` 会被伪造。

拒绝路径上不要做重活，否则攻击者用被拒绝的请求就把 CPU 打满。

## 本章问答

### 1. 999ms 为什么还失败？

**考点：** 补充是连续的，不是整秒跳变。

**回答：** 速率是每 1000ms 一个令牌。999ms 补充量不到 1，取不走。示例把时间当参数，所以不用真的睡一秒。

### 2. 多进程时限额为什么会放大？

**考点：** 内存不共享。

**回答：** 每个进程一份桶。4 个进程就是大约 4 倍。需要全集群限额时，用共享存储的原子扣减，并接受这次网络往返。

### 3. 固定窗口和令牌桶差在哪？

**考点：** 边界流量。

**回答：** 固定窗口在上一窗口的最后一秒和下一窗口的第一秒各放行一整份配额。令牌桶用容量限制突发，用速率限制长期平均。两个都要说清参数，而不是只说「做了限流」。

## 事故复盘

四个进程各有一个容量为 2 的桶，实际大约放行 8。攻击方没有碰到 429。全集群限额要共享计数。

用 `X-Forwarded-For` 的第一个值当键。调用方写成不同的地址，每请求一个新桶。只信任自己的代理。

拒绝路径上仍做同步日志压缩。被限流的请求把 CPU 打满。429 要便宜。
