# HTTP 接口

示例：`examples/B/06-http-router.mjs`。细节见 [HTTP 路由与正文](../02-进阶/06-HTTP路由与正文.md)。

对外接口先写清四件事：方法、路径、成功时的状态码和正文、失败时的状态码。不要用 200 包一层 `{ success: false }` 来表示失败，客户端和网关都不好处理。

示例的约定：

| 情况 | 状态码 |
| --- | --- |
| `GET /health` | 200，`{ ok: true }` |
| `POST /echo` 正文在上限内 | 200，原样返回 |
| 没有这条路由 | 404 |
| 正文超过 32 字节 | 413，并 `Connection: close` |
| JSON 解析失败 | 400 |

413 时先 `req.pause()`，写完响应再结束。在写出响应之前 `req.destroy()`，调用方的 `fetch` 会得到套接字错误，看不到 413。

路径从 `new URL(req.url, 'http://127.0.0.1').pathname` 取。不要用字符串 `includes` 判断路由，`/health-extra` 会误伤。

列表接口要有分页上限。创建接口如果可能被重试，接受客户端传来的幂等键，相同键返回第一次的结果。短链示例把相同 URL 映射到同一个 code，见 [系统设计](./14-系统设计.md)。

只监听需要的地址。教程示例用 `127.0.0.1` 和 `listen(0)`。


## 是什么

接口先写清方法、路径、成功时的状态码和正文、失败时的状态码。不要用 200 包一层 `{ success: false }`。网关和客户端都按状态码分类。

示例的约定见[HTTP 路由与正文](../02-进阶/06-HTTP路由与正文.md)。列表要有分页上限。创建若可能被重试，接受幂等键，相同键返回第一次的结果。短链示例把相同 URL 映射到同一个 code，见[系统设计](./14-系统设计.md)。

## 状态码

| 情况 | 状态码 |
| --- | --- |
| 读到了 | 200 |
| 创建了 | 201 |
| 没有正文的成功 | 204 |
| 参数不合法 | 400 |
| 没有登录 | 401 |
| 登录了但没有权限 | 403 |
| 没有这条资源 | 404 |
| 正文太大 | 413 |
| 超过限额 | 429 |
| 服务器自己的缺陷 | 500 |

401 和 403 不要混。413 的写出顺序见路由那一章。只监听需要的地址。教程示例用 `127.0.0.1` 和 `listen(0)`。

## 本章问答

### 1. 为什么不用 200 表示失败？

**考点：** 中间层看状态码。

**回答：** 负载均衡、浏览器和生成的客户端用状态码决定重试和告警。正文里的 `success: false` 它们看不见。失败用 4xx 或 5xx，正文只放调用方能处理的代码。

### 2. 幂等键解决什么？

**考点：** 重试造成的重复。

**回答：** 客户端超时后重试 POST，服务端可能已经创建过。键相同就返回第一次的结果，不再创建第二笔。键要由客户端生成，并在服务端唯一。

### 3. 401 和 403 怎么分？

**考点：** 身份和权限。

**回答：** 没有有效身份是 401。有身份但这个操作不允许是 403。用 404 隐藏存在性是产品决定，要写进接口说明，不要随手换。

## 事故复盘

失败也返回 200 和 `{ success: false }`。网关的错误率是 0，用户却全部失败。状态码用 4xx 或 5xx。

重试 POST 没有幂等键，订单创建了两笔。相同键返回第一次的结果。

401 和 403 混用，客户端把「没权限」显示成「请登录」，用户反复登录仍进不去。没有身份用 401，没有权限用 403。
