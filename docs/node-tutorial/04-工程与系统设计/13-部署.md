# 部署

进程由外部管理：systemd、容器或平台的进程管理器。Node 进程自己不要做「崩溃后偷偷拉起」的唯一机制，否则你会失去重启次数和日志。

镜像或发布包里包含锁文件解析出的依赖。本教程的示例没有第三方依赖，不需要安装步骤。

启动命令使用明确的 Node 主版本。这个教程的契约是 22.23。2026-11-07 时 26 已是 Active LTS，但示例没有在 26 上跑过，见 [2026 选型](./15-2026选型.md)。

环境变量在进程外注入。不要把 `.env` 打进镜像层，层会被缓存，密钥也会留下。

就绪之前不要接流量。监听成功后才算就绪。关闭时先从负载均衡摘除，再按 [优雅退出](./10-优雅退出.md) 收尾。

多核用多个进程。`cluster` 或平台的副本数都可以。进程之间不共享堆上的限流计数和会话 Map。

资源限制要设内存上限。Node 堆可以涨到 `heap_size_limit`，容器的内存上限如果只比它略大，进程会被系统杀掉而不是抛出 JavaScript 异常。


## 是什么

进程由外部监督：systemd、容器或平台。Node 进程自己不要做唯一的「崩溃后偷偷拉起」，否则你失去重启次数和日志。

本教程的示例没有第三方依赖，不需要安装步骤。有依赖的应用提交锁文件，发布包按锁文件安装。镜像里不要拷贝 `.env`，层会被缓存，密钥也会留下。

## 就绪和内存

监听成功之后才算就绪。关闭时先从负载均衡摘除，再按[优雅退出](./10-优雅退出.md)收尾。

多核用多个进程。进程之间不共享堆上的限流计数和会话。

`--max-old-space-size` 只限制 V8 老生代。容器内存上限要给 Buffer、线程栈和本机库留余量。上限太紧时，进程被杀掉，JavaScript 里没有堆溢出异常。

## 本章问答

### 1. 为什么不在代码里 while(true) 重启自己？

**考点：** 监督进程的职责。

**回答：** 自己拉起会掩盖崩溃循环，也难加上限。监督进程记录退出码、限制频率，并保留日志。应用把 `SIGTERM` 处理干净即可。

### 2. 镜像里为什么不能有 .env？

**考点：** 层和密钥。

**回答：** 构建层里的文件即使后来删除，仍可能留在历史层里。密钥由运行时注入。仓库里只放键名示例。

### 3. 堆上限和容器上限是什么关系？

**考点：** RSS 比堆大。

**回答：** 堆上限不是进程总内存。Buffer 在 `arrayBuffers` 里。容器上限应高于堆上限加上这些部分，否则系统先杀死进程。

## 事故复盘

进程自己 `while` 重启。崩溃循环没有次数上限，日志被冲掉。交给监督进程。

容器内存等于堆上限。Buffer 上传把 RSS 推过上限，进程消失，没有 JavaScript 异常。给 `arrayBuffers` 留余量，并限制上传大小。

镜像里 COPY 了 `.env`。密钥留在层缓存里。运行时注入。
