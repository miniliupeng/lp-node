# 依赖注入与切面

示例：`examples/D/10-di.mjs`。类型元数据的限制见[权限与类型剥离](../03-运行时/14-权限与类型剥离.md)。

## 是什么

控制反转：对象不自己 `new` 依赖，由外部把依赖交进来。依赖注入是具体做法，常用构造函数参数。

示例的容器用字符串令牌登记工厂。`users` 的工厂调用 `resolve('db')`。`db` 是单例，两次 `resolve` 得到同一个对象，工厂只执行一次。测试可以把 `db` 换成内存实现，不用连真实数据库。

## 为什么剥离模式不能自动看见参数类型

一些框架在类上放装饰器，编译器再把构造函数的参数类型写成 `design:paramtypes`。这要求 TypeScript 的 `experimentalDecorators` 和 `emitDecoratorMetadata`，并且要真的跑 `tsc`。Node 22 的类型剥离不生成这段元数据。因此「类上标了 `@Injectable()` 就能自动注入」依赖的是编译器，不是 JavaScript 引擎。

本教程的容器把令牌写在 `register` 里。少了魔法，换实现时你看得到依赖。循环依赖在这种容器里会变成 `resolve` 的递归，要在登记时拆开，而不是等栈溢出。

## 请求经过的切面

常见顺序是：

1. 中间件：日志、跨域、正文解析。
2. 守卫：只回答允许还是拒绝。
3. 拦截器前半：计时开始。
4. 管道：校验和类型转换。
5. 处理函数。
6. 拦截器后半：包装响应、结束计时。
7. 异常过滤器：上面没接住的错误变成响应。

守卫里不要改数据，管道里不要做鉴权。混在一起之后，测试要同时准备登录态和 JSON，失败时也不知道是哪一层。

## 本章问答

### 1. 注入怎样让测试少碰数据库？

**考点：** 依赖是参数。

**回答：** 函数或类只调用传进来的对象。测试传入内存实现，断言调用了 `query('ada')`。内部 `new` 真实驱动时，测试要么连数据库，要么去改模块系统。

### 2. 装饰器元数据从哪来？

**考点：** 编译器开关。

**回答：** 从 `emitDecoratorMetadata` 来。Node 的类型剥离不写 `Reflect.defineMetadata`。没有这段数据，框架无法从构造函数参数猜出令牌。显式登记在 22.23.4 上一定做得到，示例就是这样。

### 3. 守卫和管道为什么要分开？

**考点：** 单一职责。

**回答：** 守卫的结果是放行或拒绝。管道的结果是合法的值或 400。放在一起时，401 和 400 的条件缠在同一个函数里，顺序一变就出现「没登录却先报字段错误」或相反。

## 事故复盘

类内部 `new Database()`。测试要么连真实库，要么不稳定。改成从容器取 `db`，示例里工厂只执行一次。

在类型剥离下使用靠 `design:paramtypes` 的框架，构造参数是空的，依赖是 `undefined`。Node 不生成这段元数据。令牌写在 `register` 里。

守卫里做了字段转换，管道里做了鉴权。未登录用户先看到 400 的字段错误，泄露了接口形状。守卫只放行或拒绝，管道只产合法的值。
