# 流式生成与取消

示例：`examples/D/12-sse-cancel.mjs`。事件格式见[服务器发送事件](../02-进阶/14-服务器发送事件.md)。

## 是什么

生成式接口常常是一次 HTTP 请求，服务端按 token 写出 `text/event-stream`。用户关掉页面或点停止时，客户端中止 `fetch`。服务端若不停，会继续占用模型和连接。

示例的服务端在循环里写 token，每两个之间等 40ms。`req` 的 `close` 把 `stopped` 设为 true，循环退出。客户端读到第一块就 `abort`，并取消 reader。随后断言已经写出的条数大于等于 1，且小于全部 5 条。

## 为什么不能只在客户端停

客户端停止读取，字节可能还在服务器的缓冲里继续生成。要在请求的 `close` 或传入下游的 `AbortSignal` 上停掉模型调用。`Promise.race` 一个超时不会取消原来的工作，见[拒绝与取消](../03-运行时/13-拒绝与取消.md)。

代理缓冲会把「流式」变成「最后一起到」。这个响应要关闭缓冲。心跳用 SSE 注释行，避免中间设备认为连接空闲并断开。

结束时写一条约定好的 `data: [DONE]`，或者直接结束响应。客户端要能处理中途断开，而不是一直等到 `[DONE]`。

## 和 MCP 的 SSE

这里的 SSE 是给浏览器或 `fetch` 的响应正文。2026-07-28 的 MCP 也可以在一次 POST 的响应里使用 SSE，但那是协议帧，不是聊天产品的 token 格式。不要共用一个解析器却不看 `Content-Type` 和协议版本。

## 本章问答

### 1. 用户点击停止之后，服务器哪一行应该停？

**考点：** `close` 和下游信号。

**回答：** `req.on('close')` 里标记停止，循环不再 `write`。若还在等模型，就把同一个 `AbortSignal` 传给那次调用。只停止 `res.write` 而模型继续跑，账单和 CPU 都还在。

### 2. 为什么示例不断言恰好发出 1 条？

**考点：** 调度。

**回答：** 中止到达之前，循环可能已经写了第二条。断言是「至少一条，且没有把五条都写完」。精确等于 1 会在慢机器或快机器上翻车。

### 3. [DONE] 是 HTTP 的一部分吗？

**考点：** 应用约定。

**回答：** 不是。SSE 只规定事件怎么分帧。`[DONE]` 是一些聊天接口自己的结束标记。客户端断开时可能收不到它，结束条件应包含流关闭和中止，不能只认这个字符串。

## 事故复盘

客户端 `abort` 之后服务端仍把剩余 token 写完并调用模型。账单没停。`req` 的 `close` 必须让循环退出，并把信号传给上游。

测试断言「恰好发出 1 条」。慢机器上中止到达前又写了一条，测试闪烁。示例只断言大于等于 1 且小于全部条数。

把 `[DONE]` 当成唯一结束条件。连接中途断开时客户端一直等。结束条件包括流关闭和中止。
