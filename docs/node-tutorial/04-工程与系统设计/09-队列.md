# 队列

示例：`examples/D/03-queue.mjs`。

示例是内存队列，用来说明可见性超时，不是可持久化的消息系统。进程一退出，队列就没了。

`push` 放入任务。`pull(now, visibilityMs)` 取走一条当前可见的任务，并把 `visibleAt` 设成 `now + visibilityMs`。这段时间里别人看不到它。`ack` 才真正删除。

示例的时间线：

1. `pull(0, 1000)` 取到任务。
2. `pull(500, 1000)` 得到 `undefined`，任务仍在可见性窗口内。
3. `pull(1000, 1000)` 再次取到同一条。这是至少一次投递：处理者如果没 ack 就崩溃，超时后任务会再出现。
4. `ack` 之后 `size()` 为 0。

因此处理函数必须能安全地执行多次，或者用业务主键挡住重复。只做一次的扣款不能假设消息只到一次。

生产队列还要持久化、死信和堆积告警。可见性超时要长于正常处理时间，否则任务会被两个消费者同时处理。


## 是什么

示例是内存队列，用来说明可见性超时。`pull` 把任务隐藏 `visibilityMs`。只有 `ack` 才删除。隐藏到期后同一条会再次出现。这是至少一次，不是恰好一次。进程退出后队列消失。

时间线：0ms 取到，500ms 取不到，1000ms 又能取到，`ack` 之后长度为 0。

## 消费者要能做两次

扣款、发信、建单都可能执行两次。用业务主键挡住重复，或者让第二次变成无操作。可见性超时要长于正常处理时间，否则两个消费者会同时处理一条。

生产队列还要持久化、死信和堆积告警。处理失败到一定次数就进入死信，不要无限立刻重试。堆积意味着消费速度低于生产速度，加消费者之前先看是不是下游变慢。

## 本章问答

### 1. 至少一次和恰好一次差在哪？

**考点：** 超时后再投递。

**回答：** 隐藏不是删除。消费者崩溃而没有 `ack`，超时后消息再出现。恰好一次要业务上的去重，队列本身这一份示例做不到。不要说「用了队列就只到一次」。

### 2. 为什么超时不能短于处理时间？

**考点：** 并发重复。

**回答：** 处理还没完，消息已经可见，另一个消费者会拿走。两边一起写。超时设得比正常处理长，并给处理本身设上限。

### 3. 内存队列缺了什么？

**考点：** 持久化。

**回答：** 进程一退出数据就没了，也不能在多个实例之间共享。它只用于把可见性和 `ack` 讲清楚。生产用能够落盘、有死信的实现。

## 事故复盘

消费者扣款不查重。可见性超时后消息再来，扣了两次。至少一次要求业务主键挡住第二次。

超时设得比处理时间短。两个消费者同时拿到同一条，库存减成负数。超时要长于正常处理，处理本身要有上限。

用内存队列当生产邮件系统。进程一重启，未 ack 的邮件消失。示例只说明 `ack` 和可见性。
