# 日志

示例：`examples/D/07-logger-als.mjs`。

一条日志是一行 JSON，至少包含级别、消息和请求 id。人读的多行文字在生产里难检索。

```javascript
function log(level, message) {
  const requestId = als.getStore()?.requestId ?? null;
  return JSON.stringify({ level, message, requestId });
}
```

示例同时跑两个 `als.run`。中间有 `await` 之后，`req-a` 和 `req-b` 仍各写各的 id。存储外面的调用得到 `requestId: null`。

请求入口用 `storage.run({ requestId }, () => handle(req, res))`。不要用 `enterWith` 包住整段服务器回调之后还指望它在请求结束时自动消失。

不要记录令牌、密码、完整银行卡号或未裁剪的请求体。错误对象可以进服务端日志，堆栈不要放进 HTTP 响应。

级别建议固定为 `debug`、`info`、`warn`、`error`。用环境变量选择最低输出级别。`console.log` 在小脚本里够用，多进程时交给标准输出，由外部收集器收走。


## 是什么

一条日志是一行 JSON。至少有时间、级别、消息、请求 id。人读的多行文字在收集器里难检索。示例 `examples/D/07-logger-als.mjs` 在两个并发的 `run` 里各写各的 id，存储外面是 `null`。

## 不要记什么

不记令牌、口令、完整卡号、未裁剪的请求体。错误可以进服务端日志。堆栈不要放进 HTTP 响应。级别固定为 `debug`、`info`、`warn`、`error`，用环境变量选最低级别。

多进程时每个进程写自己的标准输出，由外部收集。不要在应用里自己打开一个共享日志文件再不加锁。请求 id 要放进跨进程消息，Worker 不会继承 `AsyncLocalStorage`。

## 本章问答

### 1. 为什么并发请求的 id 不会串？

**考点：** `AsyncLocalStorage.run`。

**回答：** 每次 `run` 有自己的 store。`await` 之后 `getStore()` 仍是进入时那一份。全局变量做不到这一点。示例断言 `req-a` 和 `req-b`。

### 2. 日志为什么要一行 JSON？

**考点：** 收集。

**回答：** 收集器按行切。多行堆栈若没有约定，会被切成多条无关日志。把堆栈放进一个 JSON 字符串字段。级别用固定单词，方便过滤。

### 3. 什么不该出现在日志里？

**考点：** 秘密。

**回答：** 口令、会话令牌、密钥、完整支付账号。调试完的正文采样要有长度上限，并去掉这些字段。

## 事故复盘

日志把 `Authorization` 原样打出。收集器被更多人能看，令牌等于公开。写日志前删掉令牌、口令和卡号。

多行 `console.log` 堆栈被收集器切成多条。改成一行 JSON，堆栈放在一个字段里。

Worker 里的日志没有请求 id。异步存储不会跨 Worker。id 放进消息。
