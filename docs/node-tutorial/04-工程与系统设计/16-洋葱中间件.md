# 洋葱中间件

示例：`examples/D/09-compose.mjs`。

## 是什么

中间件是包在真正处理函数外面的函数。线性模型和洋葱模型差在 `next` 之后还能不能回到自己的后半段。

线性模型里，`next()` 把控制权交给下一个，当前函数若在 `next()` 之后还有代码，要靠回调或响应结束事件才能再跑，异步错误也容易离开原来的 `try`。洋葱模型里每个中间件 `await next()`。`await` 之前是请求进来的方向，`await` 之后是响应出去的方向。外层的 `try/catch` 能接住内层抛出的拒绝。

示例的顺序是：

```text
a-before → b-before → handler → b-after → a-after
```

外层捕获内层错误时，顺序里会出现 `a-catch:`，而不是 `a-after`。

## 为什么要禁止 next 调用两次

`compose` 若允许同一个中间件调用两次 `next`，内层会执行两遍，写库、加头都会重复。示例用下标记住已经进到哪一层，回退就拒绝，错误信息是 `next called twice`。

这是 Koa 风格 `compose` 的核心，不是某个框架的私有函数。Express 风格的中间件不保证回到后半段。讲「我们用了中间件」时要说明是哪一种。

## 错误放在最外层

计时也放在外层：记录开始，`await next()`，回来再算差值。这样一次请求的全部内层时间都算进去。内层自己计时只能看到自己。

不要在洋葱里做无界的同步工作。`await next()` 让出的是这个异步函数，不是其他请求的主线程。大循环仍会堵住进程。

## 本章问答

### 1. 为什么洋葱适合做统一错误处理？

**考点：** `await next` 的返回。

**回答：** 内层的 `throw` 和拒绝都会变成外层 `await` 的拒绝。最外层一个 `try/catch` 可以格式化响应。线性回调要把错误作为 `next(err)` 逐层手动传递，漏一次就挂起或落到进程级异常。

### 2. next 两次会怎样？

**考点：** 重复进入内层。

**回答：** 没有保护时，处理函数跑两次。示例直接拒绝第二次。业务中间件不要在分支里各调用一次 `next`。

### 3. 这和 Fastify 的钩子是什么关系？

**考点：** 不要把两种模型说成同一个函数。

**回答：** 洋葱是函数嵌套。Fastify 的 `onRequest`、`preHandler`、`onResponse` 是按名字排好的钩子，见[路由树与序列化](./17-路由树与序列化.md)。两种都能做计时和错误处理，但执行顺序的说法不同，不能拿 Express 的 `next` 去套 Fastify 的钩子名。

## 事故复盘

中间件在两个分支里各调用一次 `next`。创建订单的处理函数跑了两次。`compose` 发现下标回退就拒绝，示例断言错误信息是 `next called twice`。

把 Fastify 的 `preHandler` 讲成 `await next()` 的后半段。那是钩子名单，不是洋葱。计时若依赖「回来之后」，要确认框架真的会回来。

外层没有 `try/catch`，内层拒绝变成未处理拒绝。最外层要接住并写成响应。
