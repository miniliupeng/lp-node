# 配置

示例：`examples/B/12-env.mjs`。行为说明见 [环境变量](../02-进阶/12-环境变量.md)。

配置在进程启动时读入，校验失败就非 0 退出。不要在第一个请求里才发现端口不是数字。

`process.env` 的值全是字符串。缺键是 `undefined`。端口用 `Number` 再检查 `Number.isInteger`，并限制在 1 到 65535。

`process.loadEnvFile` 在 22.23.4 上有三条必须记住的行为：

- 已经存在的环境变量不会被文件覆盖。示例因此先删掉目标键再加载。
- 未加引号的 `#` 开始注释。`HASH=a#b` 得到 `"a"`。
- 引号会被去掉。`APP_NAME="demo app"` 得到 `demo app`，`QUOTED="a#b"` 得到 `a#b`。

本地开发可以用 `.env`，并且不要提交它。仓库里放一份只有键名的示例文件。生产环境由进程管理器注入变量，而不是把生产文件打进镜像。

密钥出现在日志、错误响应或 `ps` 的命令行里，都算出泄漏。命令行参数会被进程列表看到，密钥放环境变量或密钥管理服务。


## 是什么

配置是进程启动时就固定下来的数据：端口、数据库路径、密钥、日志级别。它不是请求正文。来源是环境变量或平台的密钥管理，不是仓库里的 `.env`。

## 失败要发生在监听之前

把字符串解析成整数和枚举。缺键、空字符串、端口不是 1 到 65535 的整数，都非 0 退出。不要等第一个请求。

`loadEnvFile` 的三条行为见[环境变量](../02-进阶/12-环境变量.md)：不覆盖已有变量，未加引号的 `#` 开始注释，引号会被去掉。生产由进程管理器注入。文件只在本地开发使用，并且不提交。

命令行参数会出现在进程列表里。密钥放环境变量或密钥服务，不放 `argv`。日志和错误响应里也不打印密钥。

## 本章问答

### 1. 为什么后加载的 .env 不应该赢？

**考点：** 平台注入优先。

**回答：** 22.23.4 的 `loadEnvFile` 不覆盖已有键。编排系统注入的生产值会留着。若你期望文件盖过环境，这个 API 做不到，也不该在生产依赖这种覆盖。

### 2. 配置校验和请求校验有什么差别？

**考点：** 时机。

**回答：** 配置错了，进程就不该接流量。请求错了，回 400，进程继续。两套都要白名单和类型，但失败的处理不同。

### 3. 密钥放哪里？

**考点：** 泄漏面。

**回答：** 环境或密钥管理服务。不进 git，不进镜像层，不进 `ps`，不进日志。仓库里只留键名示例。

## 事故复盘

第一个请求才 `Number(process.env.PORT)`，值是空字符串，监听失败时流量已经进来。缺配置要在 `listen` 之前非 0 退出。

`.env` 被打进镜像层。后面的层删了文件，历史层里仍有密钥。运行时注入，仓库只留键名。

`loadEnvFile` 没盖过编排系统的变量，有人改文件重试了十分钟。22.23.4 不覆盖已有键。
