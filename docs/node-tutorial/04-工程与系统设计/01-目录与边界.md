# 目录与边界

一个能长期改的 Node 服务，先把代码按变化原因分开，而不是按技术名词堆在一个文件里。

```text
src/
  http/        路由、状态码、请求体上限
  domain/      业务规则，不依赖 req/res
  data/        SQL 或文件访问
  config/      启动时读入并校验的配置
```

依赖只朝一个方向走：HTTP 调用领域规则，领域规则调用数据访问。数据访问不反向 `import` 路由。这样换数据库或换 HTTP 框架时，规则函数还能单独测。

本教程的示例故意写成单文件，方便 `node examples/...` 直接跑。它们演示一个机制，不是推荐的仓库布局。

边界上的几条约定：

- 领域函数接收普通对象，返回普通对象或抛带 `code` 的错误。不接收 `IncomingMessage`。
- 外部输入在边界校验一次，见 [校验](./05-校验.md)。进了领域层就当成已经检查过。
- 密钥、端口、数据库路径来自环境，不写进源码。见 [配置](./02-配置.md)。
- 日志在边界带上请求 id，见 [日志](./03-日志.md)。

进程里不要放「全局当前用户」。并发请求会互相覆盖。请求范围的数据放进 `AsyncLocalStorage`，或者显式传参。


## 是什么

按变化的原因分目录，而不是按技术名词把所有东西堆进一个文件。HTTP 知道请求和状态码。领域函数只接收已经校验过的普通对象。数据访问只把领域操作变成 SQL 或文件读写。

## 依赖只能朝一个方向

路由可以调用领域，领域可以调用数据访问。数据访问不要 `import` 路由。这样换数据库或换 HTTP 库时，规则函数还能单独测。本教程的示例故意写成单文件，方便 `node examples/...` 直接跑。它们演示一个机制，不是推荐的仓库布局。

进程里不要放「全局当前用户」。并发请求会互相覆盖。请求范围的数据用 `AsyncLocalStorage.run`，或者显式传参。

外部输入在边界校验一次，见[校验](./05-校验.md)。进了领域层就当成已经检查过。密钥来自环境，见[配置](./02-配置.md)。

## 本章问答

### 1. 领域函数为什么不能接收 req？

**考点：** 边界。

**回答：** `req` 把套接字、流和头都带进来。领域函数一旦依赖它，离开 HTTP 就测不了，换框架时要改规则。边界把正文收成 `{ name, age }` 再传进去。

### 2. 单文件示例和这个目录建议矛盾吗？

**考点：** 教学代码和生产布局。

**回答：** 不矛盾。示例要能一条命令跑完，所以把机制放在一个文件里。服务变大之后按上面的方向拆。不要为了凑目录先建空文件夹。

### 3. 全局当前用户会出什么错？

**考点：** 并发覆盖。

**回答：** 请求 A 写入全局变量后 `await`，请求 B 把同一个变量改成自己。A 恢复时用了 B 的用户。用 `run` 或把用户当参数传递。

## 事故复盘

领域函数接收 `req`，单元测试只好起一个真服务器。后来换框架，规则函数全部改签名。边界把正文收成普通对象再传进去。

数据访问模块 `import` 了路由里的权限函数，测试数据库要带 HTTP。依赖只能从外向内。示例写成单文件是为了能一条命令跑，不是生产布局。
