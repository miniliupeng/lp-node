# 内存

示例：`examples/C/06-memory.mjs`

`process.memoryUsage()` 里常见字段：

- `rss`：进程驻留内存，含堆、栈、共享库
- `heapUsed` / `heapTotal`：V8 堆
- `arrayBuffers`：ArrayBuffer 与 Buffer 占用

示例分配 1MB 的 `Buffer.alloc`，`arrayBuffers` 随之上升。`v8.getHeapStatistics().heap_size_limit` 大于当前已用堆。到达堆上限后仍分配会触发垃圾回收，回收不掉就会内存不足。

闭包、全局缓存、未解除的监听器会保住对象。`Buffer` 即使 JavaScript 引用还在，它的字节在 V8 堆之外，所以只看 `heapUsed` 会漏掉大块内存。

`performance.now()` 是单调时钟，适合量间隔。`Date.now()` 会被系统校时影响。

不要在请求路径上无界地 `Buffer.concat`。先定上限，见[HTTP 路由与正文](../02-进阶/06-HTTP路由与正文.md)。


## 是什么

`process.memoryUsage()` 把几块不同的内存分开报。`rss` 是进程驻留集。`heapUsed` / `heapTotal` 是 V8 堆。`arrayBuffers` 是 `ArrayBuffer` 和 Buffer 的字节。`external` 是 V8 管理之外、仍由它记账的一部分内存。

## 看错字段会漏掉泄漏

分配 1MB 的 `Buffer.alloc`，`arrayBuffers` 上升，`heapUsed` 不会按同样幅度上升。只盯着堆，会觉得大文件上传没有占内存。`v8.getHeapStatistics().heap_size_limit` 大于当前已用堆。到达堆上限后仍分配会触发回收，回收不掉就内存不足。容器的内存上限如果只比堆上限略大，进程可能先被系统杀掉，JavaScript 里看不到异常。

闭包、全局缓存、未 `off` 的监听器、无上限的 `Buffer.concat` 会保住对象。`subarray` 还能保住整块底层存储，见[字节与 Buffer](../02-进阶/01-字节与Buffer.md)。

`performance.now()` 是单调时钟。`Date.now()` 会被校时影响。

## 本章问答

### 1. 大 Buffer 该看哪个字段？

**考点：** 堆外字节的记账位置。

**回答：** 看 `arrayBuffers`，同时看 `rss`。`heapUsed` 只告诉你 JavaScript 对象。`--max-old-space-size` 不限制 RSS。

### 2. 什么引用会在请求结束后把对象留住？

**考点：** 可达性。

**回答：** 被定时器、全局 `Map`、监听器闭包抓住的对象。`AsyncLocalStorage` 适合放请求 id，不适合放整份用户对象或连接。监听器要用原来的函数引用才能 `off`。

### 3. 为什么容器会杀掉一个还没抛异常的进程？

**考点：** 两种上限。

**回答：** V8 的堆上限和 cgroup 的内存上限不是同一个数。Buffer、线程栈和本机库都算在 RSS 里。cgroup 先到，进程收到的是杀死信号，不是 `JavaScript heap out of memory`。

## 事故复盘

只给容器设了和 `--max-old-space-size` 一样的内存上限。上传用 Buffer，RSS 先到上限，进程被杀掉，日志里没有堆溢出。上限要给 `arrayBuffers` 留余量，上传本身要有字节上限。

监控只画 `heapUsed`。泄漏的是监听器抓住的大 Buffer，图是平的。同时看 `arrayBuffers` 和 `rss`。
