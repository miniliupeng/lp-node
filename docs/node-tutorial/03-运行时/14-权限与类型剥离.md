# 权限模型与类型剥离

示例：`examples/C/14-permission.mjs`、`C/15-types-strip.mjs`、`C/16-message-channel.cjs`。

## 权限

不加 `--permission` 时，`process.permission` 是 `undefined`，文件系统不受这套模型限制。

```bash
node --permission --allow-fs-read=/tmp -e 'require("node:fs").readFileSync("/etc/hostname")'
```

22.23.4 上得到 `ERR_ACCESS_DENIED`。`--allow-fs-read=/etc/hostname` 后同一读取成功。

这是进程级允许名单，不是用户级鉴权。它限制脚本能碰哪些资源。HTTP 里的登录状态仍要自己做。

## 类型剥离

`process.features.typescript === "strip"`。

```bash
node examples/C/strip-sample.ts
```

可擦除的类型注解会被去掉，程序打印 `5`。Node 不做类型检查，类型错误的 `.ts` 只要擦完能跑就会跑。

`enum` 不是可擦除语法。直接运行 `enum-sample.ts` 失败，stderr 含 `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX`。加上 `--experimental-transform-types` 后打印 `1`，并带实验警告。

`using` 在 22.23.4 是语法错误。

类型检查交给 `tsc --noEmit`。运行时剥离只解决「不用先编译就能执行」这件事。


## 是什么

权限模型是进程级允许名单。不加 `--permission` 时，`process.permission` 是 `undefined`，文件系统不受这套模型限制。`--permission --allow-fs-read=/tmp` 去读 `/etc/hostname`，得到 `ERR_ACCESS_DENIED`。把该路径加入允许名单后读取成功。它不代替登录和授权。

类型剥离是另一件事。`process.features.typescript === "strip"`。可擦除的类型注解会被去掉，程序照样跑，Node 不做类型检查。`enum` 不是可擦除语法，直接运行得到 `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX`。加上 `--experimental-transform-types` 才能跑，并打印实验警告。`using` 在 22.23.4 是语法错误。

## 类型系统里剥离做不到的事

类型收窄、`satisfies`、工具类型、装饰器元数据都是给 `tsc` 看的。`node file.ts` 把它们擦掉或直接拒绝。`design:paramtypes` 只有在 TypeScript 打开 `experimentalDecorators` 和 `emitDecoratorMetadata` 并真正编译时才会生成。单靠 Node 剥离，依赖注入容器看不到构造函数的参数类型。见[类型收窄](../01-入门/14-类型收窄.md)和[依赖注入与切面](../04-工程与系统设计/18-依赖注入与切面.md)。

## 本章问答

### 1. --permission 是不是用户权限？

**考点：** 进程允许名单。

**回答：** 不是。它限制这个进程能读哪些文件、能连哪些网络。HTTP 里的登录状态仍要自己做。不加这个开关时，`process.permission` 是 `undefined`，不要假设默认就在保护。

### 2. node app.ts 为什么不能代替 tsc？

**考点：** 剥离和检查。

**回答：** 剥离只去掉它认识的类型语法。类型错误只要擦完还能跑，就会跑。`enum` 要实验开关。检查用 `tsc --noEmit`。本仓库不安装 TypeScript，所以示例只断言剥离和 `enum` 的失败。

### 3. 为什么 Nest 风格的自动注入在剥离模式下没有参数类型？

**考点：** 元数据是编译器生成的。

**回答：** `design:paramtypes` 来自 `emitDecoratorMetadata`，不是 JavaScript 运行时的默认行为。Node 22 的类型剥离不生成它。容器要显式登记令牌，见 `examples/D/10-di.mjs`。

## 事故复盘

生产命令加了 `--permission` 但没加监听端口所需的网络允许项，进程启动失败。允许名单要包含真正要读的路径和要连的地址。它不是默认开启的，不加开关时 `process.permission` 是 `undefined`。

`node app.ts` 能跑，就跳过了 CI 里的 `tsc`。类型错误的字段照样上线。剥离不是检查。`enum` 在没开实验开关时直接启动失败，报 `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX`。

依赖注入框架在剥离模式下拿不到构造函数参数类型，启动时空指针。令牌要显式登记，见 `examples/D/10-di.mjs`。
