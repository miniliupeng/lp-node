# 循环依赖

示例：`examples/C/12-circular-*.mjs`、`12-tdz-*.mjs`、`12-cjs-*.cjs`。

ESM 是活绑定。`a` 导入 `b`，`b` 导入 `a`。若在 `b` 初始化期间直接读取 `a` 里尚未初始化的 `const`，得到 `ReferenceError`（暂时性死区）。示例动态导入 `12-tdz-a.mjs` 并断言这个错误。

如果 `b` 只是导出一个函数，函数在两边都初始化完之后才被调用，就能读到已经赋好的绑定。`fromB()` 返回 `{ bName: 'module-b', seen: 'module-a' }`。

CJS 导出的是 `module.exports` 上的属性。循环进行中对方拿到的是当时已经挂上的字段。示例里 `b` 初始化时 `a.done` 仍是 `false`；两边都结束后，`a` 能看到 `b.done === true`。

ESM 评价失败会被缓存。第二次导入同一 URL 得到的仍是第一次的拒绝，不会自动重试。

能拆开的依赖就拆开。循环通常说明两个模块互相知道对方的实现。


## 是什么

两个模块互相导入。ESM 的绑定在初始化完成前处于暂时性死区，读它得到 `ReferenceError`。CJS 的 `exports` 对象从一开始就存在，对方只能看见当时已经赋上的属性。

## 两种示例

`fromB()` 在两边都初始化完之后调用，返回 `{ bName: 'module-b', seen: 'module-a' }`。动态导入 `12-tdz-a.mjs` 时期望 `ReferenceError`。

CJS 示例里，`b` 初始化时 `a.done` 仍是 `false`。两边结束后，`a` 能看到 `b.done === true`。这不是「CJS 循环一定得到空对象」。

ESM 求值失败会被缓存。第二次导入同一 URL 仍是第一次的拒绝，不会自动重试。

能拆开的依赖就拆开。循环通常说明两个模块互相知道对方的实现。把共享类型或常量放到第三个模块，循环经常就没了。

## 本章问答

### 1. 什么时候 ESM 循环会抛 ReferenceError？

**考点：** 暂时性死区。

**回答：** 在对方完成初始化之前读取它的 `const` 或 `let`。如果只是导出函数，函数在初始化之后才被调用，读取是安全的。示例把这两种情况都跑了。

### 2. CJS 循环为什么有时能读到一半？

**考点：** `exports` 对象是逐步填的。

**回答：** `require` 返回的是同一个 `exports` 对象。已经赋的属性可见，还没赋的是 `undefined`。后面再赋的属性，持有这个对象的人以后能看见。原始值如果已经被读进局部变量，后面的重新赋值不会更新那个局部变量。

### 3. 失败的 ESM 会不会每次都重试？

**考点：** 模块缓存。

**回答：** 不会。失败的求值也按 URL 记住。修了文件之后要新进程，或者接受运行时没有公开的「删掉 ESM 缓存」API。不要在生产里靠反复 import 来重试初始化。

## 事故复盘

ESM 在模块顶层读对方的 `const`，进程启动即 `ReferenceError`。改成函数里读，初始化完成后再调用，示例 `fromB()` 能看到两边的值。

CJS 在循环里读到 `done === false`，于是跳过了必须的初始化。那不是永久的 false，是当时还没赋值。不要在循环的半截状态上做业务决定。

求值失败被缓存后，热重载不生效。新进程再验证。
