# 拒绝与取消

示例：`examples/C/13-cancel-and-rejection.mjs`

`Promise.reject(new Error('boom'))` 且没有 `catch`、没有 `await`。22.23.4 上这个进程非 0 退出，stderr 含 `boom`。这是 Node 15 之后的默认行为。

注册了 `unhandledRejection` 之后，默认退出不再发生，哪怕监听器是空的。空监听器会把失败藏起来。需要监听时，记录错误并设置非 0 退出码。

`readFile(path, { signal })` 在信号已经 abort 时拒绝，`code` 是 `ABORT_ERR`，`name` 是 `AbortError`。`timers/promises` 的 `setTimeout` 被中止时，`name` 同样是 `AbortError`。

`AbortSignal.timeout(ms)` 和 `AbortSignal.any(signals)` 在 22.23.4 是函数。超时用来限制一次请求的下游调用。客户端断开时，把请求的 `AbortSignal` 传给文件、fetch 和数据库，避免工作在响应已经没人收之后继续做完。

`EventEmitter` 的 `'error'` 没有监听器会抛异常并使进程崩溃，见[事件](../01-入门/11-事件.md)。


## 是什么

没有 `catch`、也没有 `await` 的 `Promise.reject`，在 22.23.4 上让进程非 0 退出，stderr 里有错误信息。这是 Node 15 之后的默认行为。Node 14 及更早只打警告。

注册 `unhandledRejection` 之后，默认退出不再发生，哪怕监听器是空的。空监听器把失败藏起来。需要监听时记日志并设置非 0 退出码。

## 取消

`readFile(path, { signal })` 在信号已经 abort 时拒绝，`code` 是 `ABORT_ERR`，`name` 是 `AbortError`。`timers/promises` 的 `setTimeout` 被中止时，`name` 同样是 `AbortError`。

`AbortSignal.timeout(ms)` 和 `AbortSignal.any(signals)` 在 22.23.4 是函数。客户端断开时，把请求的信号传给文件、fetch 和数据库，避免响应已经没人收之后工作还做完。

`EventEmitter` 的 `'error'` 没有监听器会抛异常并使进程崩溃，见[事件](../01-入门/11-事件.md)。

## 本章问答

### 1. 监听了 unhandledRejection 之后进程还会退出吗？

**考点：** 默认行为被监听器替换。

**回答：** 不会自动退出。空函数等于把退出关掉。监听器里应记录原因。若这表示进程状态已经不可信，设置 `process.exitCode = 1` 或在收尾后退出。

### 2. AbortError 和业务错误怎么区分？

**考点：** `name` 和 `code`。

**回答：** 中止的 `name` 是 `AbortError`。文件中止还有 `code === 'ABORT_ERR'`。不要用 `message` 里的英文。用户取消通常记成 info，而不是 error 报警。

### 3. race 一个超时之后，原来的请求停了吗？

**考点：** 取消要显式传递。

**回答：** 没有。`Promise.race` 只是忽略后到的结果。原请求仍占着连接。把同一个 `AbortSignal` 传进 `fetch` 或 `readFile`，超时时 `abort()`。

## 事故复盘

为了「不被未处理拒绝搞挂」，注册了空的 `unhandledRejection`。进程不再退出，错误也没有日志，账单任务停了三天才发现。监听器里要记原因。不能继续就设置非 0 退出码。

超时只用 `Promise.race`。下游请求仍占着连接，池被占满。把 `AbortSignal.timeout` 传给 `fetch`。

把用户取消记成 error 报警。`AbortError` 是预期路径，级别用 info，避免把报警打满。
