# 异步上下文

示例：`examples/C/08-als.mjs`

`AsyncLocalStorage` 在异步跳转之间保存一份存储。`enterWith` 或 `run` 建立上下文后，`await`、Promise 和定时器回调里 `getStore()` 仍能读到。

示例同时跑两个异步函数，分别写入 `a` 和 `b`。中间有 `await`。结束时各自仍读到自己的 id。

它适合请求 id、追踪 span。不适合存放用户对象或数据库连接这种大资源，因为上下文会跟着整条异步链活着。

`enterWith` 会影响当前之后的异步资源。请求处理优先用 `storage.run(store, () => handle(req, res))`，作用域更清楚。

Worker 和子进程没有这份存储。跨进程要显式把 id 放进消息。


## 是什么

`AsyncLocalStorage` 在异步跳转之间保存一份存储。`run(store, fn)` 建立作用域。`fn` 以及它 `await` 到的回调里，`getStore()` 仍是这份 store。示例同时跑 `a` 和 `b`，中间有 `await`，结束时各自仍读到自己的 id。

## 作用域

`enterWith` 会影响当前之后的异步资源，直到另一个 `enterWith` 或 `run` 盖住它。请求处理用 `run`，作用域跟这次调用走。不要在请求中间 `enterWith` 一个新 id，后面的日志会全部变成新 id。

它适合请求 id 和追踪 span。不适合放用户对象、数据库连接或大块 Buffer。存储会跟着整条异步链活着，链有多长，对象就活多久。

Worker 和子进程没有这份存储。跨进程把 id 放进消息。日志示例见 `examples/D/07-logger-als.mjs`。

## 本章问答

### 1. 它和全局变量有什么差别？

**考点：** 并发。

**回答：** 全局变量只有一份，后一个请求会盖住前一个。`run` 为每次调用建立存储，`await` 之后不会串。示例断言 `req-a` 和 `req-b` 各读各的。

### 2. 为什么不要把数据库连接放进去？

**考点：** 生命周期。

**回答：** 连接会跟所有下游回调绑定，忘记释放时泄漏的不只是一个 id。连接用显式参数传递，用完归还到池里。存储里放不可变的小值。

### 3. enterWith 和 run 怎么选？

**考点：** 作用域是否有结尾。

**回答：** 有明确函数边界时用 `run`。`enterWith` 没有自动结尾，适合你真的知道当前资源后面全部都该换成新存储的场合。请求入口不要用它。

## 事故复盘

用全局变量 `currentUser` 在中间件里赋值，`await` 之后写审计日志。并发时日志记成了另一个用户。改成 `AsyncLocalStorage.run`。示例 `examples/D/07-logger-als.mjs` 断言两个 id 不串。

把数据库连接放进 store。请求结束后连接仍被后续的定时器闭包参照，池被耗尽。store 里只放请求 id。

Worker 里 `getStore()` 是空的，追踪断了。id 要放进 `postMessage` 的数据里。
