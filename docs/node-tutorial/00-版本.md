## 在 22.23.4 上直接确认过的点

- `process.features.typescript === "strip"`。`.ts` 里的可擦除类型可以直接跑。`enum` 抛 `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX`，加上 `--experimental-transform-types` 才能跑，并打印实验警告。剥离不做类型检查。
- `process.features.require_module === true`。`require()` 可以加载没有顶层 `await` 的 ESM。
- `import.meta.dirname` 与 `import.meta.filename` 可用。
- 全局有 `fetch`、`WebSocket`（客户端）、`crypto.subtle`。没有 `EventSource`、`URLPattern`、`localStorage`。`using` 是语法错误。
- `Object.groupBy`、`Map.groupBy`、`Promise.withResolvers`、迭代器助手、`Set.prototype.intersection`、`toSorted` / `toSpliced` 存在。
- `node:sqlite` 能建表和预编译，行对象原型是 `null`，导入时仍打印 ExperimentalWarning。
- 未处理的 Promise 拒绝默认使进程非 0 退出。注册 `unhandledRejection` 后，该默认退出不再发生。
- `setTimeout(fn, 0)` 的延迟被文档钳制成至少 1ms。主模块里它和 `setImmediate` 的先后不稳定。I/O 回调里的顺序是 nextTick、微任务、`setImmediate`、`setTimeout`。
- CJS 顶层先排空 nextTick 再排空微任务。ESM 入口的求值发生在微任务检查点里，顺序不同。见[任务队列](./03-运行时/03-任务队列.md)，并由示例断言。
- 异步 `readFile` 在这枚二进制上走 libuv 线程池：池子被 `pbkdf2` 占满时读取会等待。
- `process.loadEnvFile` 不覆盖已存在的环境变量。未加引号的 `#` 开始注释。
- 不加 `--permission` 时 `process.permission` 是 `undefined`。越权读文件得到 `ERR_ACCESS_DENIED`。
- `Buffer.poolSize` 是 8192。`subarray` 共享内存。`JSON.parse` 不会把 `__proto__` 设成原型。`structuredClone` 丢掉类方法。`timingSafeEqual` 在长度不同时抛 `ERR_CRYPTO_TIMING_SAFE_EQUAL_LENGTH`。`node:crypto` 有 `scrypt`，没有 `argon2`。


## 这些结论从哪来

上表不是从旧教程抄来的口诀。`examples/` 里的脚本在本机 Node.js 22.23.4 上断言过。和常见口述不一致、但被示例钉住的有：

- ESM 入口里，微任务可以先于 `nextTick`。CJS 顶层则是 `nextTick` 先排空。见[任务队列](./03-运行时/03-任务队列.md)。
- 主模块里 `setTimeout(fn, 0)` 和 `setImmediate` 的先后不稳定。I/O 回调里 `setImmediate` 在前。
- `JSON.parse` 不会把 `__proto__` 设成对象的原型。
- `loadEnvFile` 不覆盖已有环境变量，未加引号的 `#` 开始注释。
- 未处理的拒绝默认使进程非 0 退出。空的 `unhandledRejection` 监听器会取消这个退出。
- 异步 `readFile` 在这枚二进制上仍会等待被 `pbkdf2` 占满的线程池。
- 全局没有 `EventSource`、`URLPattern`、`localStorage`。`using` 是语法错误。`enum` 不能被类型剥离直接执行。

MCP 的传输修订见[模型上下文协议](./04-工程与系统设计/19-模型上下文协议.md)。那一章依据的是 2026-07-28 规范文本，不是本仓库跑出来的网络服务。

换 Node 主版本之后重跑 `node examples/run-all.mjs`。断言失败就改文档，不要改断言去迁就旧句子。
