# 流与背压

示例：`examples/B/02-backpressure.mjs`

流让数据一块一块走，避免整份文件进内存。

- 可读流：`read()` 或 `for await`
- 可写流：`write()` / `end()`
- 转换流：一边读一边改

`write()` 返回 `false` 表示内部缓冲已达到 `highWaterMark`。此时停止再写，等到 `drain` 再继续。示例把水位设为 1，`write` 返回 `false`，然后等到 `drain`。

`stream.promises.pipeline(source, dest)` 负责转发错误，并在失败时销毁两边。示例让目标在第一次 `write` 抛错，`pipeline` 以该错误拒绝。

`res` 也是可写流。把大文件 `pipe` 到 `res` 时要接住 `'error'`，否则管道断了没人知道。`pipeline` 比手写 `pipe` 少漏错误。

消费可读流时读完或明确销毁。HTTP 请求体没读完就返回，连接可能一直占着。正文上限见[HTTP 路由与正文](./06-HTTP路由与正文.md)。


## 是什么

流把数据分成块。可读流产出，可写流接收，转换流两边都做。`highWaterMark` 是内部缓冲的上限提示，不是硬性的内核限制。

## 为什么忽略 write 的返回值会 OOM

`write()` 返回 `false` 表示缓冲已经达到水位。这时继续 `write`，数据堆在进程内存里。正确做法是停下来，等 `drain` 再写。示例把水位设为 1，能看见 `false` 和随后的 `drain`。

`stream.promises.pipeline(source, dest)` 在任一边出错时销毁两边，并把错误传给调用方。手写 `pipe` 必须自己接 `error`，否则管道断了没人知道，读端可能继续生产。

消费可读流时要读完或明确销毁。HTTP 请求体没读完就返回，连接会一直占着。正文上限见[HTTP 路由与正文](./06-HTTP路由与正文.md)。

## 对象模式和字节模式

默认的文件流和网络流是字节。`objectMode: true` 的流里每个块是一个任意值，水位按对象个数算，不按字节。不要把对象模式的流直接接到 `res` 上。

## 本章问答

### 1. write 返回 false 之后做什么？

**考点：** 背压。

**回答：** 停止写入，监听一次 `drain` 再继续。不要在 `false` 之后自旋。`pipeline` 会替你处理这段暂停。返回值是提示，不是异常。

### 2. pipe 和 pipeline 差在哪？

**考点：** 错误转发。

**回答：** `pipe` 不自动转发错误，也不在失败时销毁两端。`pipeline` 会。生产里用 `stream.promises.pipeline`。中间如果要改数据，放一个转换流，而不是自己拼事件。

### 3. 为什么读了一半就返回会占住连接？

**考点：** 请求体也是可读流。

**回答：** 剩下的字节还在套接字缓冲里，对端还在等你读。keep-alive 连接因此不能复用。要么读完，要么在确定不要正文时销毁请求，并让响应带上 `Connection: close`。超限的写法见路由那一章，不要在写出 413 之前先 `destroy`。

## 事故复盘

文件流 `pipe` 到响应，磁盘读失败时没有 `error` 监听器，进程崩溃，客户端收不到结束。改用 `pipeline`，它会销毁两端并把错误交出来。

忽略 `write` 返回的 `false`，继续把数据库行写入一个慢的套接字。内存涨到容器上限，进程被杀掉，JavaScript 没有堆溢出栈。`false` 之后等 `drain`。

请求体没读完就返回 200。keep-alive 连接不能复用，表现是后续请求卡住。要么读完，要么在不要正文时结束连接。
