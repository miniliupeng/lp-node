# WebSocket

示例：`examples/B/15-websocket.mjs`

22.23.4 的全局 `WebSocket` 是客户端。没有内置的 WebSocket 服务器。示例自己实现了握手和一小段 RFC 6455。

握手：客户端发 `Upgrade: websocket` 和 `Sec-WebSocket-Key`。服务端把 key 与固定 GUID `258EAFA5-E914-47DA-95CA-C5AB0DC85B11` 拼接，做 SHA-1，再 base64，放进 `Sec-WebSocket-Accept`，状态码 101。

帧：客户端发往服务端的帧必须掩码，服务端发往客户端的帧不掩码。示例处理 opcode `0x1` 文本、`0x8` 关闭、`0x9` ping、`0xA` pong。不完整的帧留在缓冲里。单帧上限 1 MiB。

客户端连上后发送 `hi`，收到 `echo:hi`。

这是教学实现，没有协商扩展、分片消息和 `permessage-deflate`。生产用经过维护的库，并限制连接数和消息大小。


## 是什么

## 帧

客户端到服务端的帧必须掩码，反方向不掩码。示例处理 opcode `0x1` 文本、`0x8` 关闭、`0x9` ping、`0xA` pong。不完整的帧留在缓冲里。单帧上限 1 MiB。没有协商扩展，没有分片消息，没有 `permessage-deflate`。

长连接要有心跳。一段时间没有 pong 就关掉，否则对端消失后服务器还留着这组对象。重连和退避放在客户端。生产用经过维护的库，并限制连接数和消息大小。

## 本章问答

### 1. 有全局 WebSocket 是不是就有服务器？

**考点：** 客户端 API 和服务端实现。

**回答：** 不是。全局对象用来发连接。接受升级、计算 Accept、解析帧要自己写或用库。示例能把 `hi` 变成 `echo:hi`，同时把没做的部分写清楚。

### 2. 为什么服务端帧不掩码？

**考点：** RFC 6455 的方向。

**回答：** 规范要求客户端掩码，防止中间缓存把客户端数据当成另一段 HTTP。服务端帧不掩码。两边都掩码或都不掩码，对端会解出乱码。

### 3. 教学实现还缺什么？

**考点：** 不要把示例当库。

**回答：** 分片、扩展、压缩、每条消息的内存上限之外的连接数上限、以及心跳超时。这些没做。业务服务使用维护中的实现，并自己限制大小和数量。

## 事故复盘

把全局 `WebSocket` 当成服务器。`new WebSocket(url)` 是去连接别人。接受升级要自己算 `Sec-WebSocket-Accept` 或使用库。示例只覆盖文本帧、关闭、ping/pong 和 1MiB 上限。

服务端也按客户端的方式掩码，浏览器解出来是乱码。客户端到服务端必须掩码，反方向不掩码。

没有心跳。笔记本合上之后服务器仍留着这组对象，连接数单调上涨。一段时间没有 pong 就关闭。
