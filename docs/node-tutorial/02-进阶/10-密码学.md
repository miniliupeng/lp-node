# 密码学原语

示例：`examples/B/10-crypto.mjs`

`Math.random()` 不能生成令牌、密钥或重置码。用 `crypto.randomBytes` 或 `crypto.randomUUID`。

`createHash('sha256').update(data).digest('hex')` 与 `crypto.subtle.digest('SHA-256', ...)` 对同一段字节结果相同。示例断言这一点。哈希不能解密。相同输入永远得到相同输出，所以低熵密码不能只存一层裸哈希。

`createHmac('sha256', secret).update(body).digest()` 用于校验「持有密钥的人生成了这段字节」。JWT 的 HS256 就是 HMAC，见[会话与 JWT](../04-工程与系统设计/06-会话与JWT.md)。

`timingSafeEqual` 比较两段摘要。长度不同时 22.23.4 抛 `ERR_CRYPTO_TIMING_SAFE_EQUAL_LENGTH`。先判断长度，再调用它。普通 `===` 会在第一个不同字节处返回，比较时间会泄露信息。

`scrypt` 存在。`argon2` 不在 `node:crypto` 里。密码存储用慢哈希，并带独立盐。示例只调用 `scrypt` 确认 API，不把它的参数当成生产口令策略。

密钥放在环境或密钥管理服务里，不进仓库。


## 是什么

哈希把任意字节变成固定长度摘要，不能反推，相同输入得到相同输出。HMAC 在哈希里混入密钥，用来确认持有密钥的人生成了这段字节。它们都不是加密。加密要能用密钥还原明文，那是另一组 API。

## 比较和口令

`timingSafeEqual` 在长度不同时抛 `ERR_CRYPTO_TIMING_SAFE_EQUAL_LENGTH`。先比长度，再调用它。普通 `===` 会在第一个不同字节返回，比较时间会随差异位置变化。

`Math.random` 不能生成令牌、会话 id 或重置码。用 `randomBytes` 或 `randomUUID`。

口令不能只存一层 SHA-256。相同口令得到相同摘要，还能预计算。`node:crypto` 有 `scrypt`，没有 `argon2`。示例只确认 `scrypt` 能调用，不把示例参数当成生产口令策略。盐要每个口令独立，用 `randomBytes` 生成。

SHA-256 和 `crypto.subtle.digest('SHA-256', ...)` 对同一段字节结果相同。示例断言了这一点。

JWT 的 HS256 就是 HMAC，见[会话与 JWT](../04-工程与系统设计/06-会话与JWT.md)。密钥放在环境或密钥管理服务里，不进仓库，不进命令行。

## 本章问答

### 1. 哈希、HMAC、加密有什么差别？

**考点：** 三个词经常被说成一个。

**回答：** 哈希没有密钥，不能还原。HMAC 有密钥，用来验证完整性，也不能还原明文。加密用密钥把明文变成密文，并可以用对应密钥还原。签名不是加密，JWT 载荷谁都能解开。

### 2. 为什么 timingSafeEqual 要先看长度？

**考点：** 这个函数的前置条件。

**回答：** 22.23.4 上长度不同会抛 `ERR_CRYPTO_TIMING_SAFE_EQUAL_LENGTH`，而不是返回 false。捕获这个错误可以当成不相等，但要分清它和别的异常。不要为了让长度相同就在用户输入后面补零再比较口令，那会改变比较的含义。

### 3. 口令为什么不能只做 SHA-256？

**考点：** 速度和彩虹表。

**回答：** SHA-256 太快，又能预计算。口令存储用 `scrypt` 这类慢哈希，每个口令一把盐。标准库没有 `argon2`，需要它就用单独维护的实现，不要假装 `crypto` 里有这个名字。

## 事故复盘

口令库只存 SHA-256。泄露后可以用预计算表还原常见口令。改用 `scrypt` 和每条口令独立的盐。标准库没有 `argon2`，不要在依赖清单里写一个不存在的 `crypto.argon2`。

`timingSafeEqual` 没先看长度，长度不同就抛 `ERR_CRYPTO_TIMING_SAFE_EQUAL_LENGTH`，被上层当成 500。先比长度，不相等就当验证失败。

用 `Math.random` 生成重置链接。它不是密码学随机数。用 `randomBytes` 或 `randomUUID`。
