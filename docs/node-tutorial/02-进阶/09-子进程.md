# 子进程

示例：`examples/B/09-child-process.mjs`

用 `spawn(command, argsArray, options)`，参数放数组。示例执行：

```javascript
spawn('node', ['-e', 'console.log(process.argv[1])', 'a; rm -rf /tmp/x'], {
  stdio: ['ignore', 'pipe', 'pipe'],
});
```

分号留在参数里，被打印出来，不会变成新的命令。`/tmp/lp-node-should-not-exist` 在运行后不存在。

`shell: true` 会经过 shell 解析。用户字符串里的 `;`、`$()`、反引号会变成新命令。默认不要开。

子进程结束看 `code` 和 `signal`。非 0 是失败。`error` 事件表示根本没启动起来，例如找不到可执行文件。

`exec` 会缓冲全部输出。大输出用 `spawn` 自己读流，并限制长度。

子进程继承的环境变量里可能有密钥。需要干净环境时显式传入 `env`。


## 是什么

`spawn(file, args, options)` 直接创建进程，参数是数组，不经过 shell。`exec` 走 shell 并缓冲全部输出。`fork` 是给另一个 Node 脚本准备的 `spawn`，自带 IPC 通道。

## 为什么 shell: true 危险

shell 会解释 `;`、`$()`、反引号和重定向。用户字符串进了这条命令，就变成新的命令。示例把含分号的字符串放进 `argv`，它被原样打印，`/tmp/lp-node-should-not-exist` 不会被创建。默认不要开 `shell: true`。必须用 shell 时，不把用户输入拼进命令字符串。

`error` 事件表示没启动起来，例如找不到可执行文件。进程启动之后的失败看退出码 `code` 和 `signal`。非 0 是失败。`exec` 缓冲全部 stdout，大输出会把内存打满，改用 `spawn` 自己读流并限制长度。

子进程继承环境变量。密钥会跟着过去。需要干净环境时显式传入 `env`，并且用 `process.execPath` 而不是字符串 `'node'`。

## 本章问答

### 1. spawn 和 exec 怎么选？

**考点：** shell 和缓冲。

**回答：** 有参数、输出可能很大、输入来自用户时用 `spawn` 加参数数组。`exec` 适合你完全控制的短命令，并且你接受它把输出全放进内存。`shell: true` 不是默认值，打开之后参数不再安全。

### 2. 退出码和 error 事件有什么差别？

**考点：** 启动失败和运行失败。

**回答：** `error` 是操作系统没把进程跑起来。`exit` 的 `code` 是它跑完之后的状态。两者都要处理。只监听 `exit` 会漏掉 `ENOENT`。

### 3. 为什么子进程里的 node 要用 execPath？

**考点：** PATH。

**回答：** `'node'` 取决于 PATH，CI 和本机可能不是同一个二进制。`process.execPath` 就是当前这个进程的二进制，版本和编译选项一致。

## 事故复盘

把用户路径拼进交给 shell 的命令字符串，分号会变成第二条命令。改成 `spawn` 加参数数组。示例把含分号的字符串放进 `argv`，它被打印出来，不会执行。

`exec` 拉取大日志，全部进内存，进程被容器杀掉。大输出用 `spawn` 流式读，并限制字节数。

子进程用字符串 `'node'`。CI 的 PATH 上是另一条主版本，脚本用了当前版本没有的 API。改用 `process.execPath`。
