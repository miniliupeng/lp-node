# 环境变量

示例：`examples/B/12-env.mjs`

`process.env.PORT` 是字符串。缺键是 `undefined`。数字要 `Number` 以后再检查 `Number.isInteger`。

`process.loadEnvFile(path)` 读取类似 dotenv 的文件。22.23.4 上：

- 已存在的环境变量不会被覆盖
- 未加引号时，`#` 开始注释，所以 `HASH=a#b` 得到 `"a"`
- 引号会被去掉，`APP_NAME="demo app"` 得到 `demo app`，`QUOTED="a#b"` 得到 `a#b`

示例先删掉这几个键，再加载临时文件，所以结果只来自文件。`finally` 里删掉临时键并恢复原来的 `TUTORIAL_PORT`。

`.env` 不提交。仓库里可以放 `.env.example`，只写键名。生产环境由进程管理器注入变量。

不要把密钥打进日志。启动时检查必填项，缺了就非 0 退出，而不是在第一个请求里才发现。


## 是什么

`process.env` 是进程启动时拿到的字符串表。`loadEnvFile` 按类似 dotenv 的规则补进一些键。22.23.4 上它不覆盖已存在的键。未加引号的 `#` 开始注释。引号会被去掉。

## 为什么要先删键再测

开发机上如果已经导出了 `APP_NAME`，文件里的值不会生效，测试会偶发失败。示例因此先 `delete` 那几个键，再加载临时文件，`finally` 里恢复 `TUTORIAL_PORT`。生产环境由进程管理器注入变量，后到的 `.env` 不应该盖过它们。这是特性，不是 bug。

`.env` 不提交。仓库里可以放只有键名的示例文件。密钥出现在日志、错误响应或 `ps` 里都算出泄漏。命令行参数在进程列表里可见，密钥不要放那里。

启动时把端口、必填密钥解析成类型。缺了或不是整数就非 0 退出。不要在第一个请求里才发现 `PORT` 是 `"abc"`。

## 本章问答

### 1. loadEnvFile 会不会覆盖现有变量？

**考点：** 22.23.4 的实际行为。

**回答：** 不会。已存在的键保持原值。测试要先删掉目标键。生产上这能防止文件盖过平台注入的密钥，也能让你误以为改了文件就会生效。

### 2. HASH=a#b 为什么变成 a？

**考点：** 注释规则。

**回答：** 未加引号时 `#` 开始注释。要保留 `#` 就写成 `QUOTED="a#b"`，读出来是 `a#b`，引号本身被去掉。`APP_NAME="demo app"` 得到 `demo app`。

### 3. 配置应该在什么时候失败？

**考点：** 失败前移。

**回答：** 监听端口之前。缺必填项就退出，监督进程会重启或让发布失败。拖到第一个请求，健康检查可能已经通过，流量进来才爆。

## 事故复盘

生产注入了 `DATABASE_URL`，镜像里又有一份 `.env`。`loadEnvFile` 不覆盖已有值，改文件没有生效，排错的人以为加载器坏了。这是 22.23.4 的规则。本地测试要先删掉目标键。

`HASH=a#b` 读成 `a`，签名密钥少了一截，所有请求 401。含 `#` 的值加引号。

密钥写进启动参数，`ps` 能看到。改成环境变量或密钥服务，日志里打红acted 而不是原值。
