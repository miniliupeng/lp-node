# node:test

示例：`examples/B/11-sample.test.mjs`

```bash
node --test examples/B/11-sample.test.mjs
```

`node:test` 在 Node 22 是稳定的。`test('name', async () => {})` 登记一条用例。失败的断言使该用例失败，进程非 0 退出。

`import { mock } from 'node:test'`。`mock.fn((a, b) => a + b)` 仍执行你的实现，同时记录 `mock.calls`。示例断言一次调用的参数是 `[2, 3]`、结果是 5。

`mock.timers` 仍是实验 API，本教程的防抖测试不使用它，见 `examples/E/04-debounce.mjs`。

`run-all.mjs` 在跑完脚本后执行这条测试。忘了 `await` 异步断言时，测试会在拒绝发生前结束。

覆盖率：

```bash
node --experimental-test-coverage --test examples/B/11-sample.test.mjs
```

开关名字在 22.23.4 仍带 experimental。


## 是什么

`node --test` 收集 `test()` 登记的用例。失败的断言使该用例失败，进程非 0 退出。`node:test` 在 Node 22 是稳定 API。`mock.fn` 也按稳定能力使用。`mock.timers` 和 `--experimental-test-coverage` 在 22.23.4 仍带实验标记。

## 怎样写一条不会说谎的用例

异步用例必须 `await` 断言。漏掉 `await`，测试函数先返回，拒绝发生在用例被标成通过之后。

`mock.fn(impl)` 仍执行 `impl`，同时记下参数和结果。示例断言一次调用的参数是 `[2, 3]`、结果是 5。不要用实验性的假时钟去测防抖。`examples/E/04-debounce.mjs` 注入 `{ set, clear }`，测试里手动调用保存下来的回调。

覆盖率数字不是正确性。没覆盖到的分支可能是 413、中止和退出路径，那些更值得补。

## 本章问答

### 1. 哪些测试 API 可以写进长期规范？

**考点：** 稳定和实验。

**回答：** `node:test`、`assert/strict`、`mock.fn` 可以。`mock.timers` 和覆盖率开关在 22.23.4 的名字或行为仍可能变。生产代码不要依赖假时钟的内部实现。

### 2. 异步测试怎样会假通过？

**考点：** 返回的 Promise 没被等待。

**回答：** `test('x', () => { assert.rejects(...) })` 没有 `await`，运行器不知道还有一个拒绝。写成 `async` 并 `await`，或者返回那个 Promise。

### 3. 为什么防抖测试不调用 mock.timers？

**考点：** 把时间变成参数。

**回答：** 假时钟仍是实验 API。注入的 `set` 只保存回调，`clear` 把它清掉。连续调用两次后手动执行最后一次回调，就能断言只触发一次，而且不依赖墙上时钟。

## 事故复盘

覆盖率 90% 但 413 和中止分支没有用例。线上第一次超限时 `destroy` 的顺序是错的，客户端看不到状态码。覆盖率不是那些分支的替代品。

实验性假时钟写进了共享测试工具，升级 Node 后一批测试超时。时间用注入的 `set` 和 `clear`。`node:test` 和 `mock.fn` 可以留在长期规范里。

漏掉 `await` 的用例在报告里是通过，进程却因未处理拒绝而失败。CI 若只看测试摘要，会放行这个提交。
