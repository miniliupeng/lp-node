## 1

**题目：** `timingSafeEqual` 在两段长度不同时会怎样？密码哈希用什么？

**难度：** 进阶

**考察点：** 比较函数的前置条件和标准库里有什么。

**参考答案：** 22.23.4 抛 `ERR_CRYPTO_TIMING_SAFE_EQUAL_LENGTH`。先判断长度，再比较。普通 `===` 会在第一个不同字节返回。`Math.random` 不能生成令牌。`node:crypto` 有 `scrypt`，没有 `argon2`。SHA-256 和 `crypto.subtle.digest` 对同一输入结果相同。哈希不能解密。

**易错点：** 不看长度就调用 `timingSafeEqual`，把异常当成「不相等」的正常返回。

## 2

**题目：** 为什么 JWT 实现不能信任头里的 `alg`？签名是加密吗？

**难度：** 深入

**考察点：** 算法混淆和载荷可见性。

**参考答案：** 调用方可以改头。按头选算法时，可能被换成 `none`，或换到另一把密钥。示例只接受 `HS256`，其他算法失败。签名是 HMAC，不是加密，任何人都能解开载荷。`exp` 按秒比较。密钥用高熵随机值，不把 `test-secret` 带进生产。

**易错点：** 先 `JSON.parse` 头，再按 `alg` 分支，把 `none` 当成「没有签名所以通过」。

## 3

**题目：** 用户输入 `ada' OR '1'='1` 时，参数化查询应该返回几行？

**难度：** 基础

**考察点：** 注入改变的是语句结构，不是参数值。

**参考答案：** 当参数传入时，匹配行数是 0。只有把它拼进 SQL 文本，才会变成额外的条件。示例用 `?` 占位。多条写入放在事务里，失败就回滚。

**易错点：** 自己把引号转义一遍，再拼进 SQL。转义规则和数据库方言绑在一起，占位符由驱动处理。

## 4

**题目：** `path.resolve(root, userPath)` 之后还要做什么，才能拒绝 `../`？

**难度：** 进阶

**考察点：** 绝对路径会替换前面的部分，以及符号链接。

**参考答案：** `path.resolve('/var/app', '/etc/passwd')` 得到 `/etc/passwd`。所以要再算 `path.relative(root, resolved)`。相对结果以 `..` 开头或是绝对路径就拒绝。示例对 `../secret`、`/etc/passwd`、`a/../../secret` 抛 `E_PATH_ESCAPE`，`a/../b.txt` 仍在根内。目录里的符号链接还要在打开后用真实路径再查。

**易错点：** 只判断字符串里有没有 `..`，于是拒绝了合法的 `a/../b.txt`，却放过了以绝对路径形式传入的地址。


## 5

**题目：** Cookie 的 `HttpOnly`、`Secure`、`SameSite` 各限制什么？

**难度：** 进阶

**考察点：** 三个属性不是同一种攻击。

**参考答案：** `HttpOnly` 让脚本读不到 cookie。`Secure` 只在 HTTPS 发送。`SameSite=Lax` 是浏览器里常见的默认：跨站 POST 不带 cookie，顶层 GET 导航可以带。`Strict` 更紧。`None` 必须同时 `Secure`。它们不代替服务端的权限检查，也不让 JWT 载荷变加密。

**易错点：** 说 `HttpOnly` 能防 CSRF。它防的是脚本把 cookie 抄走。跨站请求是否带 cookie 要看 `SameSite`。

## 事故复盘

说 `JSON.parse` 会造成原型污染，又说 `HttpOnly` 能防 CSRF。两个都和 22.23.4 的行为或浏览器的分工不符。污染在合并。CSRF 看 `SameSite` 和令牌。`HttpOnly` 只阻止脚本读取 cookie。
