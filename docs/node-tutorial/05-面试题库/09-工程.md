## 1

**题目：** `loadEnvFile` 会覆盖已经存在的环境变量吗？`HASH=a#b` 读出来是什么？

**难度：** 进阶

**考察点：** 22.23.4 的 dotenv 兼容细节。

**参考答案：** 不会覆盖。未加引号的 `#` 开始注释，所以 `HASH=a#b` 得到 `"a"`。引号会被去掉，`QUOTED="a#b"` 得到 `a#b`，`APP_NAME="demo app"` 得到 `demo app`。测试要先删掉这些键，结果才只来自文件。`.env` 不提交。

**易错点：** 认为后加载的文件总是赢。生产环境已经注入的变量会留着，文件里的同名键不生效。

## 2

**题目：** `server.close()` 对正在处理的请求和新请求分别做什么？

**难度：** 基础

**考察点：** 优雅退出的顺序。

**参考答案：** 它停止接受新连接，已经接受的请求继续跑完。示例里 80ms 的慢请求在 `close` 之后仍返回正文，随后新的 `fetch` 失败。`SIGTERM` 的处理顺序是停止接收、停止拉新任务、等待在途请求、关数据库、再退出。`process.exit()` 会掐断在途请求。

**易错点：** 在 `close` 的回调里以为慢请求已经被取消。回调表示连接已经结束，不是「立即取消业务」。

## 3

**题目：** 两个并发请求的日志 id 为什么不会串？

**难度：** 进阶

**考察点：** `AsyncLocalStorage` 的作用域。

**参考答案：** 每个请求用 `storage.run(store, fn)` 建立自己的存储。`await` 之后 `getStore()` 仍是进入时的那一份。示例里 `req-a` 和 `req-b` 不会互换。存储外面是 `null`。不要用一个全局变量 `currentRequestId`。Worker 不会继承这份存储。

**易错点：** 在请求中间 `enterWith` 另一个 id，后面的异步回调都变成新 id。

## 4

**题目：** 校验为什么要白名单？`age: "36"` 能通过「是数字」吗？

**难度：** 基础

**考察点：** 多余字段和类型。

**参考答案：** 白名单只留下 `name` 和 `age`，调用方塞进来的 `extra` 或 `isAdmin` 不会进入返回值。`age` 必须是整数，字符串 `"36"` 拒绝。`typeof` 不能用来接受年龄，`NaN` 的 `typeof` 也是 `'number'`，要用 `Number.isInteger` 加范围。

**易错点：** `const user = { ...req.body, id }` 把客户端字段原样展开。

## 5

**题目：** `node:test` 里哪些能力在 22.23.4 是稳定的，哪些仍带实验标记？

**难度：** 进阶

**考察点：** 测试工具的版本状态。

**参考答案：** `node:test` 和 `mock.fn` 可以当稳定能力用。`mock.timers` 仍会打印实验警告，防抖示例改为注入 `{ set, clear }`。覆盖率开关是 `--experimental-test-coverage`。异步用例忘了 `await`，可能在断言之前就被标成通过。

**易错点：** 生产代码依赖 `mock.timers` 的内部行为。


## 6

**题目：** 洋葱中间件和线性中间件差在哪？`next` 为什么不能调用两次？

**难度：** 进阶

**考察点：** `await next` 的返回路径。

**参考答案：** 洋葱在 `await next()` 之后还能执行后半段，外层 `try` 接得住内层的拒绝。线性模型把控制权交出去后，不自动回到后半段。示例 `examples/D/09-compose.mjs` 的顺序是 a 前、b 前、处理函数、b 后、a 后。第二次 `next` 会拒绝，避免内层执行两遍。

**易错点：** 把所有叫 middleware 的东西都讲成洋葱。Fastify 的钩子是按名字排列的另一套顺序。

## 事故复盘

`loadEnvFile` 被说成总会用文件里的新值。生产上已有的变量不会被盖掉，排错方向整个反了。优雅退出若回答成 `process.exit`，慢请求的例子对不上 `examples/D/04-graceful.mjs`。
