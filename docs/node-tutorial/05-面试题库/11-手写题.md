# 手写题

这四题都有可运行的参考实现。先自己写，再对照示例。测试用注入的时间或假定时器，不依赖墙上时钟。

## 1 有上限的并发映射

**题目：** 实现 `mapLimit(items, limit, fn)`。同一时刻最多 `limit` 个 `fn` 在执行，结果顺序与输入一致。

**难度：** 进阶

**考察点：** 并发上限和结果下标。

**参考答案：** 见 `examples/E/01-pool.mjs`。若干 worker 共用一个下标。每个 worker 取走当前下标再加一，执行 `fn`，把结果写进 `out[index]`。`finally` 里减少正在执行的计数。worker 数量是 `min(limit, items.length)`。示例对五个元素、上限 2，峰值不超过 2，结果是 `[10, 20, 30, 40, 50]`。`limit` 不是正整数时抛 `RangeError`。

**易错点：** `Promise.all(items.map(fn))` 没有上限。先 `push` 到结果数组会在完成顺序和输入顺序不一致时排错。

**追问：** 其中一个 `fn` 拒绝时，其他正在跑的调用还要不要取消？这道题没有取消。要取消就把同一个 `AbortSignal` 传进 `fn`。

## 2 LRU

**题目：** 实现容量有限的 LRU。`get` 和 `set` 都把键变成最新。超出容量时丢掉最旧的。

**难度：** 进阶

**考察点：** `Map` 的插入顺序。

**参考答案：** 见 `examples/E/02-lru.mjs`。`Map` 按插入顺序迭代。`get` 时先删再插，键就到了末尾。`set` 已存在的键也先删再插。`size` 超过容量时，删掉 `keys().next().value`，那是最旧的。容量 2 时依次 `set a`、`set b`、`get a`、`set c`，被丢掉的是 `b`。容量小于 1 抛 `RangeError`。

**易错点：** `get` 只返回值，不更新顺序，于是最近读过的键仍被当成最旧。

**追问：** 这个 `Map` 能在 cluster 的多个进程之间共享吗？不能。

## 3 退避重试

**题目：** 实现最多 `attempts` 次的重试。失败后的等待是 `delayMs * 2 ** attempt`。全部失败则抛出最后一次错误。

**难度：** 进阶

**考察点：** 次数、退避，以及把睡眠注入进来。

**参考答案：** 见 `examples/E/03-retry.mjs`。循环从 0 到 `attempts - 1`。成功就返回。失败且还有剩余次数时 `await sleep(delayMs * 2 ** attempt)`。示例前两次失败、第三次成功，记录到的等待是 `[10, 20]`。始终失败时在两次尝试后抛出原错误。

**易错点：** 在最后一次失败之后还再睡一次。也容易把 HTTP 500 和网络拒绝混成同一种「要重试」。

**追问：** 哪些请求不能照这个函数自动重试？没有幂等键的 POST。

## 4 防抖

**题目：** 实现防抖。连续调用只保留最后一次。不要使用实验性的 `mock.timers`。

**难度：** 基础

**考察点：** 定时器抽象，以及取消上一次。

**参考答案：** 见 `examples/E/04-debounce.mjs`。返回的函数先 `clear` 上一次的句柄，再 `set` 一个新回调。回调里清空句柄并调用原函数。测试注入 `{ set, clear }`：`clear` 把保存的回调置空，`set` 再保存新回调。连续调用两次之后还没触发，手动执行保存的回调，原函数只跑一次。

**易错点：** `clear` 和 `set` 的顺序反了，于是刚设上的回调被清掉。22.23.4 的 `mock.timers` 仍是实验 API，答案不要依赖它。

**追问：** 防抖和节流差在哪？防抖把一串调用收成最后一次。节流是每个时间窗口最多执行一次，中间的调用不会全部推迟到末尾。


## 5 洋葱 compose

**题目：** 写一个 `compose`。外层能在内层之后继续执行，并且第二次 `next` 要失败。

**难度：** 进阶

**考察点：** 下标和 Promise。

**参考答案：** 见 `examples/D/09-compose.mjs`。`dispatch(i)` 若 `i <= index` 就拒绝。否则记下 `index`，调用当前中间件，并把 `() => dispatch(i + 1)` 当成 `next`。没有下一层就 resolve。示例顺序是 a 前、b 前、处理函数、b 后、a 后。

**易错点：** `next` 不返回 Promise，外层 `await` 等不到内层的异步错误。`Promise.resolve(fn(...))` 把同步抛错也变成拒绝。

## 6 显式容器

**题目：** 写一个按令牌登记的单例容器，不要依赖装饰器元数据。

**难度：** 进阶

**考察点：** 工厂和单例。

**参考答案：** 见 `examples/D/10-di.mjs`。`register(token, factory)`。`resolve` 时若已有单例就返回，否则调用工厂并把容器传进去。示例里 `db` 只构造一次，`users` 通过容器拿到同一个 `db`。Node 的类型剥离不会生成 `design:paramtypes`，所以令牌必须显式写出。

**易错点：** 在工厂里直接 `new` 具体数据库，测试就换不掉了。

## 事故复盘

`mapLimit` 用 `Promise.all(items.map)` 实现，上限不存在。LRU 的 `get` 不更新顺序，容量一满就把刚读过的键删掉。compose 不拒绝第二次 `next`，订单会创建两次。对照 `examples/E` 和 `examples/D/09-compose.mjs` 改。
