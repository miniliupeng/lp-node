# 进程与线程

正文：[子进程](../02-进阶/09-子进程.md)、[工作线程](../03-运行时/09-工作线程.md)、[多进程](../03-运行时/10-多进程.md)、[权限与类型剥离](../03-运行时/14-权限与类型剥离.md)。

## 1

**题目：** 为什么 `spawn` 的参数要用数组，而不是拼进一个 shell 字符串？

**难度：** 基础

**考察点：** 命令注入。

**参考答案：** 数组里的参数不会被 shell 解析。示例把含分号的字符串放进 `argv`，它被原样打印，不会变成新命令。`shell: true` 会把 `;`、`$()` 和反引号交给 shell。默认不要开。子进程是否启动失败看 `error` 事件，退出码看 `code`。

**易错点：** 用 `exec` 缓冲一个不受信任的大输出，内存先被打满。

## 2

**题目：** Worker 和 cluster 各共享什么？

**难度：** 进阶

**考察点：** 进程和线程的边界。

**参考答案：** Worker 是同一进程里的另一个 V8 isolate，普通对象要经 `postMessage` 结构化克隆。`SharedArrayBuffer` 才是共享内存，读写要用 `Atomics`。Worker 脚本必须是真实文件，`node -e` 的路径会 `MODULE_NOT_FOUND`。`cluster` 是多个进程，不共享 JavaScript 堆。非 Windows 上默认调度是 `SCHED_RR`。会话和限流计数不能放在进程内的 `Map` 里指望所有 Worker 都能看见。

**易错点：** 说 Worker 共享一个堆，或者 cluster 的全局变量会自动同步。

**追问：** I/O 密集的 HTTP 服务先扩什么？先扩进程。CPU 密集计算再用 Worker 池，不要每个请求新建 Worker。

## 3

**题目：** `--permission` 没打开时，`process.permission` 是什么？越权读文件的错误码呢？

**难度：** 进阶

**考察点：** 权限模型的默认值和错误码。

**参考答案：** 不加 `--permission` 时 `process.permission` 是 `undefined`，文件系统不受这套模型限制。`--permission --allow-fs-read=/tmp` 去读 `/etc/hostname`，22.23.4 得到 `ERR_ACCESS_DENIED`。把该路径加入允许名单后读取成功。这是进程级允许名单，不是用户登录状态。

**易错点：** 把权限模型当成应用里的角色鉴权。

## 4

**题目：** `UV_THREADPOOL_SIZE` 在进程跑起来之后再改 `process.env`，有用吗？

**难度：** 深入

**考察点：** 线程池大小的读取时机。

**参考答案：** 没有用。它在进程启动时读取。要比较不同池大小，就用 `spawn` 给子进程一份新的环境。22.23.4 上异步文件读取、`dns.lookup`、`pbkdf2`、`scrypt`、异步 `randomBytes` 和异步 zlib 走这个池。

**易错点：** 在服务器代码里给 `process.env.UV_THREADPOOL_SIZE` 赋值，以为后续的 `pbkdf2` 会用新大小。


## 5

**题目：** 多个 cluster Worker `listen` 同一个端口，为什么常常不会 `EADDRINUSE`？计数能共享吗？

**难度：** 深入

**考察点：** 谁持有监听套接字。

**参考答案：** 非 Windows 默认 `SCHED_RR`。主进程监听，把已经接受的连接交给 Worker。Worker 不是各自再 `bind` 一次。堆不共享，限流计数各算各的。一次杀掉全部 Worker 会中断在途请求。滚动替换是先启动新的，确认它在监听，再让旧的 `close`。

**易错点：** 说四个进程同时成功绑定了同一个端口。那是共享句柄或主进程分发，不是四次独立的成功 `bind`。

## 事故复盘

说 cluster 的四个进程各自 bind 成功所以不会冲突。追问调度策略时答不出 `SCHED_RR` 是主进程分发句柄。再说全局 Map 可以做全集群限流，这题回到 0 分。堆不共享。
