## 1

**题目：** `fetch` 在 HTTP 500 时会拒绝吗？重试要注意什么？

**难度：** 基础

**考察点：** 网络失败和 HTTP 错误状态是两回事。

**参考答案：** 不会。连不上、DNS 失败或中止才会拒绝。4xx/5xx 仍然 resolve，要看 `response.ok`。重试前把失败响应的正文读掉。默认可重试的是幂等请求。POST 创建资源不要自动重试，除非有幂等键。次数要有上限，等待要加抖动。

**易错点：** `try/catch` 包住 `fetch` 就认为已经处理了 500。

## 2

**题目：** 请求体超过上限时，为什么不能先 `req.destroy()` 再写 413？

**难度：** 进阶

**考察点：** 响应还没写出去，套接字已经被关掉。

**参考答案：** 先销毁会让客户端的 `fetch` 得到 `UND_ERR_SOCKET`，看不到 413。正确顺序是累加 `chunk.length`，超限后 `req.pause()`，写 413 并设置 `Connection: close`。坏 JSON 回 400，堆栈不进响应。路由比较 `pathname`，不要用包含关系。

**易错点：** 只限制 `Content-Length`。分块传输可以不带这个头，仍要按实际收到的字节计数。

## 3

**题目：** Node 22 有 WebSocket 服务器吗？握手时 `Sec-WebSocket-Accept` 怎么来？

**难度：** 深入

**考察点：** 全局 `WebSocket` 只是客户端。

**参考答案：** 22.23.4 的全局 `WebSocket` 是客户端，没有内置服务器。教学实现把客户端的 key 和 GUID `258EAFA5-E914-47DA-95CA-C5AB0DC85B11` 拼接，做 SHA-1，再 base64。客户端发往服务端的帧必须掩码，反方向不掩码。示例处理文本、关闭、ping 和 pong，单帧上限 1 MiB。这不是完整实现，没有扩展和分片消息。

**易错点：** 看到全局 `WebSocket` 就说服务端也能 `new WebSocket` 来接受连接。

## 4

**题目：** 怎样用 HTTP 做服务器单向推送？浏览器的 `EventSource` 在 Node 里有吗？

**难度：** 进阶

**考察点：** SSE 的帧格式和缺失的全局对象。

**参考答案：** 响应头用 `text/event-stream`，事件之间用空行分开，默认事件名是 `message`，冒号开头是注释。22.23.4 没有全局 `EventSource`。代理要关掉这段响应的缓冲。客户端断开时停止继续写。

**易错点：** 在 Node 里直接 `new EventSource`。

**追问：** 22.23.4 还有哪些常被当成「已经有了」的 Web API 其实不在？示例确认过没有 `URLPattern` 和 `localStorage`。


## 5

**题目：** 用户中止流式响应时，服务器怎样停掉后续 token？

**难度：** 进阶

**考察点：** `close` 和下游取消。

**参考答案：** 听请求的 `close`，循环不再写。若还在等模型，把 `AbortSignal` 传下去。示例 `examples/D/12-sse-cancel.mjs` 断言写出的条数小于全部 token，不断言恰好一条，因为中止到达前可能又写了一条。`[DONE]` 是应用约定，不是 HTTP 标准。客户端断开时可能收不到它。

**易错点：** 只在浏览器里 `abort`，以为服务器的循环会自己停。

## 事故复盘

说 fetch 在 500 时会抛错，于是重试逻辑写在 `catch` 里，500 实际上不会进 `catch`。流式题若只答「用 SSE」，却说不出 `close` 之后要停模型，这题停在 1 分。
