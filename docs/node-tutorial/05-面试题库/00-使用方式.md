# 使用方式

题库对应 2026-11-07 已核对的 **Node.js 22.23.4**。换到 24 或 26 之后，先重跑 `node examples/run-all.mjs`，再把和版本有关的答案改掉。

每题都按这个顺序写：

1. **题目**
2. **难度**：基础、进阶、深入
3. **考察点**
4. **参考答案**
5. **易错点**
6. **追问**

用法：先合上答案讲三分钟，再对照。讲得出「在 22.23.4 上测过的顺序」和「文档里的阶段名」是两件不同的事，都要讲。

示例文件名是英文，章节文件名是中文。答案里的路径可以直接运行。

评分口径见 [追问与评分](./12-追问与评分.md)。


## 和旧教程答案冲突时听谁的

有些流传很广的句子，在 22.23.4 上不成立，或者只在一种入口成立：

| 常见句子 | 本教程的边界 |
| --- | --- |
| nextTick 永远先于 Promise | 只在当前执行不在微任务检查点时成立。ESM 入口相反 |
| setTimeout(0) 一定先于 setImmediate | 主模块不稳定。I/O 回调里 immediate 在前 |
| JSON.parse 会污染原型 | 22.23.4 上不会。污染来自合并 |
| node file.ts 会做类型检查 | 只会剥离可擦除语法 |
| Buffer 完全不受内存限制 | 不计入 `heapUsed`，仍计入 `arrayBuffers` 和 RSS |
| MCP 的远程传输就是一条长 SSE | 2026-07-28 是每次 POST，响应才可能是 SSE |

答面试时先说版本。对方拿旧句子追问，就指出上面的边界，并说出对应示例的路径。

## 事故复盘

背完一份不带版本的题库去面试，被问 ESM 入口的顺序时仍回答 nextTick 优先。先看[版本](../00-版本.md)里和常见口诀冲突的表，再用对应示例把顺序讲出来。讲不出示例路径的答案，按[追问与评分](./12-追问与评分.md)最高 1 分。
