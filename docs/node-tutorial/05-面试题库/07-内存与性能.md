# 内存与性能

正文：[内存](../03-运行时/06-内存.md)、[性能测量](../03-运行时/11-性能测量.md)、[异步上下文](../03-运行时/08-异步上下文.md)。

## 1

**题目：** 分配一个 1MB 的 `Buffer` 之后，应该看 `memoryUsage` 的哪个字段？

**难度：** 基础

**考察点：** 堆外内存。

**参考答案：** 看 `arrayBuffers`。`Buffer.alloc` 的字节在 V8 堆之外，只看 `heapUsed` 会漏掉。`rss` 是进程驻留内存。`v8.getHeapStatistics().heap_size_limit` 大于当前已用堆。到达上限后仍分配，会触发回收，回收不掉就会内存不足。

**易错点：** 用 `heapUsed` 判断大文件上传有没有把内存打满。

## 2

**题目：** `monitorEventLoopDelay` 的数值单位是什么？它说明什么？

**难度：** 进阶

**考察点：** 先确认单位，再解释现象。

**参考答案：** 单位是纳秒。延迟变大，说明主线程有一段时间没有回到事件循环。常见原因是同步 JSON、同步压缩、大循环和 `readFileSync`。示例阻塞约 40ms，只断言最大值大于 20ms。`performance.now` 是单调时钟，适合量间隔。`Date.now` 会被系统校时影响。

**易错点：** 把纳秒读成毫秒，得出「延迟只有零点零几毫秒」的结论。

## 3

**题目：** 哪些东西会让对象在请求结束后仍然活着？

**难度：** 进阶

**考察点：** 引用关系，而不是「Node 会泄漏」。

**参考答案：** 闭包抓住的大对象、全局缓存、注册后没有 `off` 的监听器、没有上限的 `Buffer.concat`。`AsyncLocalStorage` 适合放请求 id，不适合放数据库连接或用户对象，因为上下文会跟着整条异步链。监听器要用当初那个函数引用才能摘掉。

**易错点：** 每次请求 `on` 一个新箭头函数，又从不 `off`。超过 10 个监听器时会出现警告。

**追问：** 怎样证明是事件循环被堵住，而不是数据库慢？先量主线程上的同步区间和事件循环延迟，再量数据库调用自身的耗时。两段分开看。


## 4

**题目：** `subarray` 进了缓存之后，内存曲线为什么不下降？

**难度：** 深入

**考察点：** 底层存储的生命周期。

**参考答案：** 小视图抓住整块 `ArrayBuffer`。`heapUsed` 可能几乎不动，`arrayBuffers` 仍高。要只留 4 字节就复制。事件循环延迟的单位是纳秒，和这段内存不是同一个问题：延迟高说明主线程没回来，内存高说明还有引用。两张图分开看。

**易错点：** 只调 `--max-old-space-size` 去解决 Buffer 上涨。那个参数不限制 `arrayBuffers` 和 RSS。

## 事故复盘

看到内存涨就加大 `--max-old-space-size`。Buffer 不在这个上限里。追问单位时把事件循环延迟的纳秒读成毫秒。两题都要先说清字段和单位，再谈优化。
