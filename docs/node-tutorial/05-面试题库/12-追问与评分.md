# 追问与评分

参考答案写的是 22.23.4 上核对过的行为。候选人说出不同版本时，让他说明版本，再决定这道题还算不算对。

## 怎样追问

每道题至少往下追一层，用来区分背诵和用过。

| 表面回答 | 追问 | 加分回答里要出现的东西 |
| --- | --- | --- |
| 事件循环有六个阶段 | 这段代码是 CJS 还是 ESM？ | 两种入口的 nextTick 顺序不同 |
| `setTimeout(0)` 比 `setImmediate` 早 | 在 `readFile` 回调里呢？ | 主模块不稳定，I/O 回调里 immediate 在前 |
| Promise 拒绝会打印 | 进程退出码呢？空监听器呢？ | 默认非 0 退出；空监听器取消默认退出 |
| 用了参数化查询 | 把引号拼进 SQL 和放进 `?` 差在哪？ | 只有前者会改变语句结构 |
| JWT 用了 HS256 | 头里的 `alg` 谁来信？ | 实现钉死算法，拒绝 `none` |
| 多进程能利用多核 | 限流计数放哪？ | 进程内 `Map` 不会在 cluster 之间共享 |
| 可以直接跑 TypeScript | 它检查类型吗？`enum` 呢？ | 只剥离可擦除语法；`enum` 要实验开关 |

追问仍然答不上时，停在这一层，不要改成另一道完全无关的题。

## 评分

每题按 0 到 3 分，不按「讲得流不流利」加分。

| 分 | 含义 |
| --- | --- |
| 0 | 和 22.23.4 的行为相反，或把实验 API 说成稳定契约 |
| 1 | 名词对，但说不出顺序、错误码或适用边界 |
| 2 | 主路径正确，能指出一个失败情况 |
| 3 | 主路径、失败情况和版本边界都对，并能落到本仓库的一个示例 |

现场写代码时，能跑过该题示例里的断言算 3 分。只写出函数签名算 1 分。

一组面试取语言、事件循环、网络或安全、系统设计里各一题，再加一道手写。时间不够就少拿题，不要把参考答案缩成没有边界的口诀。

## 不要这样问

- 不给版本，却要求背某一个补丁才出现的默认值。
- 用「闭卷默写 Node 源码」代替「这个失败会返回什么」。
- 把 `node:sqlite`、`mock.timers`、`--experimental-transform-types` 当成可以写进长期设计文档的稳定 API。


## 加分和扣分的具体句子

听到下面的句子，追问「在哪种入口、哪个版本」：

- 「nextTick 绝对先于一切 Promise」
- 「setTimeout(0) 一定比 setImmediate 早」
- 「parse 完 JSON 原型就被污染了」
- 「直接跑 TypeScript 就等于类型检查通过」
- 「cluster 里的全局变量每个请求都能看见」
- 「MCP 就是一条浏览器 SSE」

能说出反例并指向 `examples/` 里的脚本，这一题可以从 2 分到 3 分。把实验 API 说成可以写进长期设计，这一题是 0 分，即使后面的架构图画得完整。

## 事故复盘

评分只看「讲得流不流利」。一份把实验 API 说成长期契约、把 nextTick 说成永远优先的流畅回答是 0 分。能指出版本、反例和示例路径，才从 2 分到 3 分。
