# D01 目录与依赖方向

示例脚本是扁平的，方便一个文件跑完。应用代码要有方向，否则测试和替换都会缠在一起。

## 一种可用的划分

```text
src/
  http/        路由、状态码、读取请求体
  domain/      纯规则：计价、权限判断、状态机
  data/        SQL、文件、出站 HTTP
  main.ts      读配置、组装、listen
```

依赖只朝内：`http` 可以调用 `domain`，`domain` 不 import `node:http`，也不 import 具体的数据库驱动。`data` 实现 `domain` 需要的接口（例如 `UserStore`）。

这样 D06 的校验、D08 的令牌桶、E02 的 LRU 都可以放在 `domain`，用普通单元测试驱动，不起服务器。

## 进程入口只做组装

`main` 读取环境变量、构造数据库、构造路由、调用 `listen`、登记 `SIGTERM`。业务分支不写在入口文件里。测试可以跳过 `main`，直接调用路由函数。

## 配置不要散落

读 `process.env` 的代码集中在一处，校验后得到一个对象，再传给构造函数。其余模块接收 `port` 或 `config` 参数，方便测试传入固定值。见 D02。

## 和本仓库另一条线的关系

根目录 `00` 到 `08` 的专题是按技术点切开的 TypeScript 实验，每个目录一个 `main.ts`。那是学习切片，不是上面的应用分层。做完整服务时按依赖方向放文件，而不是按“今天学了 SQLite”放一个永远不调用的目录。

## 自测

1. 为什么领域函数不 import 数据库驱动？这样规则测试不必启动数据库，驱动也可以替换。
2. 入口文件应该做哪些事？读配置、组装依赖、监听端口、登记退出信号。
3. 路由层可以包含计价规则吗？可以调用它，规则本身放在领域模块里，避免复制到第二个入口。
