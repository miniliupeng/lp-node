# D08 限流

对应示例：[`examples/node-tutorial/D/01-token-bucket.mjs`](../../../examples/node-tutorial/D/01-token-bucket.mjs)

## 令牌桶

桶有容量 `capacity`，按 `refillPerSecond` 补充，补到容量为止。每次成功的 `tryRemove(cost)` 扣掉令牌。令牌不够就拒绝，调用方返回 HTTP 429。

示例容量 2、每秒补充 1 个：

- 时刻 0 连续两次成功，第三次失败
- 时刻 999ms 仍失败（只补充了 0.999 个）
- 时刻 1000ms 成功一次，再来一次失败

时间由参数传入，测试不依赖真实睡眠。生产调用时传入 `Date.now()`。

## 计数器放哪

示例的桶在一个进程的内存里。cluster 的每个 Worker、每个容器副本都有自己的桶。全局限流要把计数放到共享存储，并用原子操作扣减，否则两个进程会各自放行满额。

键要选对：登录接口按 IP 加账号，写接口按用户 ID。只按 IP 会误伤 NAT 后面的人，只按用户 ID 挡不住未登录的洪水。

## 失败时的行为

拒绝时返回 429，带 `Retry-After` 更好。不要在服务器里 `sleep` 到令牌够了再继续，那会占住连接。

存储不可用时要事先决定：是放行（可用性优先）还是拒绝（保护下游）。两种都说得通，写在设计里。

## 自测

1. 令牌桶和固定窗口的差别？固定窗口在窗口交界处可能放进将近两倍的量。令牌桶按补充速率平滑。
2. 为什么多副本时内存桶不是全局限流？每个进程各数各的。
3. 时刻由参数传入有什么好处？测试可以跳过 1000ms，也不受时钟拨动影响（生产仍要选单调时钟来算间隔）。
