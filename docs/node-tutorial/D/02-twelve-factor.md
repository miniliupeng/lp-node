# D02 配置、十二要素、密钥

环境文件的可运行行为见 [`B/12-env.mjs`](../../../examples/node-tutorial/B/12-env.mjs) 和 [B12](../B/12-config.md)。

## 十二要素里和 Node 直接相关的几条

- **一份代码，多份配置**。镜像或构建产物不因环境而重新编译。差别放在环境变量里。
- **配置存在环境中**。开发机可以用 dotenv 文件，文件不进 git。
- **把后端服务当附加资源**。数据库地址是配置，不是写死在源码里的主机名。
- **进程无状态**。要能杀掉并用新进程代替。状态在数据库或队列。
- **快速启动、可靠关闭**。关闭见 D10。
- **日志当事件流**。写到 stdout，由运行环境收集。见 D03。
- **开发生产尽量一致**。都用 Node 22 的同一条小版本线，而不是开发机 22、生产机 18。

## 优先级

22.23.4 的 `process.loadEnvFile` 不覆盖已经存在的变量。部署系统注入的 `APP_PORT=1111` 不会被文件里的 `9999` 盖掉。这符合“真实环境优先”。在文档里写明这条，避免有人以为改 `.env` 就能影响已经导出的变量。

未加引号的 `#` 是注释。秘密或连接串里如果有 `#`，加引号。

## 密钥

- 不进仓库，不进镜像层，不进错误响应
- 日志中间件不要打印 `req.headers.authorization` 或 `process.env`
- 轮换时，验证代码要同时接受旧密钥和新密钥一小段时间，再撤掉旧的。JWT 示例只有一把密钥，生产要做成密钥标识（`kid`）到密钥的映射
- 本地示例用短字符串当 HMAC 密钥，那只是测试夹具

## 启动失败

校验失败时打印缺少哪个键（不要打印值），把 `process.exitCode` 设为 1 并停止 `listen`。不要用默认端口悄悄启动。

## 自测

1. 为什么生产不用重新构建来改数据库地址？地址是配置，构建产物保持一份。
2. `loadEnvFile` 和已有环境变量冲突时谁赢？已有环境变量。
3. 日志为什么不能打 `process.env`？里面有密钥。
