# D07 数据访问

SQLite 示例：[`B/13-sqlite.mjs`](../../../examples/node-tutorial/B/13-sqlite.mjs)。

## 连接

每个请求打开一个数据库文件是浪费，也会把“打开失败”混进业务错误。进程启动时建立连接或连接池，请求从池里借，用完归还。池有上限，借不到时失败或排队，不要无限制地创建连接，否则会打满数据库。

`node:sqlite` 的 `DatabaseSync` 是同步 API，调用期间主线程不能跑别的 JavaScript。演示和低并发工具可以用。高并发 HTTP 服务更常见的是异步驱动。同步驱动放在请求路径上时，要知道它会拉高事件循环延迟。

## 语句

所有外部值走参数位 `?` 或具名参数。`exec` 只跑固定的迁移和事务控制语句。

查询要有 `LIMIT`。先在数据库里看计划，确认过滤字段有索引。Node 进程改写成“先全表 `all()` 再在 JavaScript 里过滤”会把表拉进内存。

## 事务

一次业务动作里的多次写入放进 `BEGIN` … `COMMIT`。中途失败就 `ROLLBACK`。示例在插入两行用户时演示了提交。

事务要短。不要在事务里 `await` 一个外部 HTTP 调用，那个调用会把锁或连接占住。

## 迁移

迁移是有顺序的 SQL 文件，每份只向前改一次模式。启动时在一张 `schema_migrations` 表里记下已经跑过的版本，没跑过的按顺序执行。不要在请求里临时 `CREATE TABLE`。

多实例同时启动时，迁移要有锁（数据库咨询锁或单独的发布步骤），避免两台一起改表。

## 自测

1. 为什么不在热路径上拼接 SQL？值会被当成语法，见 SQLite 示例里那条 OR 字符串。
2. 事务里为什么不要等外部 HTTP？事务占用的锁会一直持有。
3. 同步 SQLite 对事件循环意味着什么？调用期间主线程在忙。
