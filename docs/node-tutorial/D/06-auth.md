# D06 会话与 JWT

对应示例：[`examples/node-tutorial/D/02-jwt.mjs`](../../../examples/node-tutorial/D/02-jwt.mjs)

## 两种会话

**服务器会话**：登录成功后发一个随机 ID，放在 `Set-Cookie` 里，数据存在服务器（内存只适合单进程演示，多进程放数据库或缓存）。Cookie 带 `HttpOnly`、`Secure`、`SameSite`。注销就是删掉服务器上的那条记录。

**JWT**：服务器用密钥给一段 JSON 签名，令牌自己带 `sub` 和 `exp`。任何持有密钥的服务都能验证，不必查会话表。注销做不到“立刻让已发出的令牌失效”，除非再加一张吊销表，那就又回到了会话存储。

需要立刻注销、或令牌里不想放个人数据时，用服务器会话。需要多个服务验证、且能接受过期前无法单方面作废时，用短寿命 JWT，并用刷新流程换新令牌。刷新令牌按口令那样保存（只存哈希），放在更严的 Cookie 里。

## 示例做了什么

`signHs256` 生成 `header.payload.signature` 三段，都是 base64url。签名是 HMAC-SHA256，覆盖前两段。`verifyHs256`：

1. 必须是三段
2. 头和载荷能解析成 JSON
3. `alg` 必须是 `HS256`。`none` 直接 `reason: 'alg'`
4. 用同一密钥重算 HMAC，长度相同才 `timingSafeEqual`
5. `nowSeconds >= exp` 则 `reason: 'exp'`

断言覆盖：正确密钥在过期前通过；错误密钥是 `sig`；时刻等于 `exp` 失败；改载荷而沿用旧签名是 `sig`；`alg: none` 失败。

## 这不是加密

载荷是 base64url，任何人都能解码。不要把口令或刷新令牌放进 JWT 载荷。签名保证的是“持有密钥的人签过这些字节”，不是保密。

## 实现时还要守住的点

- 只接受你实现了的算法。不要按令牌头里的 `alg` 去选密钥或改用公钥。示例把算法钉死为 `HS256`
- 密钥长度要够。测试夹具的短字符串不能拿到生产
- `exp` 用秒，和 `Date.now()/1000` 同一单位。示例把“现在”当参数传入，测试不必睡眠
- 生产用成熟库，并跟上安全通告。示例是为了把字节和比较看清楚

## Cookie 属性

`HttpOnly`：JavaScript 读不到。`Secure`：只在 HTTPS 发送。`SameSite=Lax` 或 `Strict`：减少跨站自动发送。会话 Cookie 不要同时让前端脚本能读。

## 自测

1. JWT 的签名段是加密吗？不是，是 HMAC。
2. 为什么拒绝 `alg: none`？否则攻击者可以去掉签名说“这是无算法令牌”。
3. 怎样立刻注销一个 JWT？纯 JWT 做不到。需要吊销列表或改用服务器会话。
