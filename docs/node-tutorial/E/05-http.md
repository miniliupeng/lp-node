# E05 网络与 HTTP

### Q1. TCP 为什么要应用层定界？

- 难度：初级
- 考察点：字节流
- 参考答案：一次 `write` 可能被拆开，多次 `write` 可能粘在一次 `data` 里。示例用 4 字节大端长度加正文，解析器保留不完整的尾部，并拒绝超过 1 MiB 的声明长度。把两帧一次写入，服务器能拆出 `one` 和 `two`。
- 易错点：按“一次 data 事件一条消息”写协议。
- 追问：UDP 呢？数据报有边界，但可能丢、重复、乱序。

### Q2. `server.listen(0, '127.0.0.1')` 是什么意思？

- 难度：初级
- 考察点：绑定
- 参考答案：端口 0 让系统分配空闲端口，只接受回环地址。实际端口从 `server.address()` 读。对外服务才绑定所有接口。示例在 `address()` 不是 TCP 地址对象时抛错。
- 易错点：把 0 说成“随机但固定的 3000”。
- 追问：忘记 `res.end` 会怎样？客户端一直等到超时。

### Q3. HTTP 正文为什么必须读？

- 难度：中级
- 考察点：流与连接复用
- 参考答案：`req` 是可读流。不读完，对端和代理无法结束这次消息，连接也不能复用。超限时暂停并返回 413，带 `connection: close`。示例上限 32 字节，64 字节的 POST 得到 413。
- 易错点：只在 `end` 事件里看 `req.body`。原生 `http` 没有解析好的 `req.body`。
- 追问：`fetch` 对 HTTP 500 会抛错吗？不会。要看 `response.ok`。网络失败和中止才会拒绝。

### Q4. 哪些请求可以自动重试？

- 难度：中级
- 考察点：幂等
- 参考答案：没有副作用的读，或带服务端幂等键的写。500/502/503/504 和网络错误可以在次数和退避之内重试。400 和 404 重试无意义。示例里的服务第一次 500、第二次 200，客户端读掉失败响应的正文再重试。无条件重试 `POST /payments` 可能扣款两次。
- 易错点：见 500 就立刻循环，没有上限。
- 追问：退避加抖动为什么？避免所有客户端在同一秒重试。

### Q5. SSE 和 WebSocket 怎么选？

- 难度：中级
- 考察点：方向与实现成本
- 参考答案：只需要服务器推文本时用 SSE：普通 HTTP，`text/event-stream`，空行分事件，默认事件名 `message`。22.23.4 没有 `EventSource`，Node 客户端用 `fetch` 读流。需要双向或二进制帧时用 WebSocket。Node 有客户端，没有内置服务器。示例按 RFC 6455 计算 `Sec-WebSocket-Accept = base64(sha1(key + GUID))`，解开客户端掩码，回 `echo:hi`。
- 易错点：说 Node 22 的 `WebSocket` 可以 `listen`。
- 追问：多机器时连接表放哪？每台机器只保存自己接受的套接字，消息经发布订阅送到持有连接的那台。

### Q6. 反向代理后面的客户端 IP 怎么取？

- 难度：高级
- 考察点：信任边界
- 参考答案：只在连接确实来自你的代理时才读 `X-Forwarded-For`，并取代理追加的那一跳。客户端可以自己写这个头。直接对公网的 Node 进程用套接字的远端地址。
- 易错点：永远取头里的第一个值。
- 追问：TLS 在谁那里终止？通常在代理。Node 只听内网。
