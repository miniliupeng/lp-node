# E04 Buffer、流、文件

### Q1. `Buffer.alloc` 和 `allocUnsafe` 的差别？

- 难度：初级
- 考察点：未初始化内存
- 参考答案：`alloc` 把字节填 0。`allocUnsafe` 不保证内容，可能含有旧数据。小于 `Buffer.poolSize`（22.23.4 为 8192）的 unsafe 分配可能来自池。对外写出之前必须覆盖每个字节。示例只断言 unsafe 的长度，不断言它是 0。
- 易错点：一次观察到全 0 就说 unsafe 会清零。
- 追问：池的目的？减少小块分配次数。

### Q2. `subarray` 和复制的差别？

- 难度：中级
- 考察点：共享内存
- 参考答案：`subarray` 是同一块内存的视图。改视图会改原缓冲。示例把 `abcdef` 改成 `aZcdef`。`Buffer.from(view)` 会复制，改副本不影响原缓冲。`Buffer#slice` 在这个版本也是共享，且没有弃用警告；`Uint8Array#slice` 才是复制。新代码用 `subarray`。
- 易错点：按 TypedArray 的 `slice` 记忆 Buffer。
- 追问：字符串 `length` 和 `Buffer.byteLength`？`'héllo'` 是 5 个码元、6 个 UTF-8 字节。

### Q3. 什么是背压？

- 难度：中级
- 考察点：`write` 的返回值
- 参考答案：生产者快过消费者时，`writable.write` 返回 `false`，表示内部缓冲达到 `highWaterMark`。调用方等待 `drain` 再写。示例把水位设为 1，两次写里至少一次返回 `false`，最终两块都写完。不管返回值会让缓冲涨到占满内存。`pipeline` 会按这个节奏拉数据，并在失败时销毁流。
- 易错点：把 `highWaterMark` 说成不可越过的配额。继续写仍然可以，只是在告诉你该停。
- 追问：`pipe` 和 `pipeline`？`pipeline` 转发错误并销毁。`pipe` 要自己听 `error`。

### Q4. 怎样原子地替换一个配置文件？

- 难度：中级
- 考察点：同目录 `rename`
- 参考答案：写到同一目录的临时文件，再 `rename` 到目标名。同一文件系统上的替换对读者是完整旧文件或完整新文件。跨设备会 `EXDEV`。示例不做 `fsync`，所以它不承诺断电不丢。并发写者使用不同临时名，最后一个 `rename` 获胜。
- 易错点：说 `writeFile` 自带原子性。
- 追问：符号链接？字符串检查不够，打开后还要看真实路径。

### Q5. 大文件为什么不能 `readFile` 再 `res.end`？

- 难度：初级
- 考察点：内存
- 参考答案：`readFile` 把整个文件放进一个 Buffer。用 `pipeline` 把文件可读流接到 `res`，内存量级是水位而不是文件大小。`stream/consumers` 的 `text()` 同样会读完整流，只适合小响应。
- 易错点：先 `stat` 再决定。即使知道很大，也不该整读。
- 追问：Web 流怎么接？`Readable.fromWeb` / `toWeb`，示例把 `你好Node` 转了一圈再读回来。

### Q6. `fs.readFile` 会不会占线程池？

- 难度：高级
- 考察点：不要背过时的后端假设
- 参考答案：在 22.23.4 的这次实验里会。`UV_THREADPOOL_SIZE=1` 且唯一线程在跑 `pbkdf2` 时，`readFile` 要等；池子为 4 且只有一个 `pbkdf2` 时，`readFile` 很快。libuv 的 io_uring 后端在不同版本默认值不同，回答时带上版本和实验，而不是说“所有 Node 的 fs 都永远走线程池”。
- 易错点：说异步 fs 不消耗任何线程。
- 追问：同步 `readFileSync` 呢？它占主线程，不把工作丢进池子。
