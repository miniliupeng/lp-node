# E10 系统设计

设计题先要数字：QPS、正文大小、p99、保留期、一致性要求。Node 进程放在哪一层要说清楚。

### Q1. 设计短链。

- 难度：中级
- 考察点：读多写少与可猜测性
- 参考答案：`POST` 校验 `http/https`，生成不可预测的短码，冲突则重试，存 `code -> url`。`GET` 返回 302。读路径用缓存。示例用递增 36 进制和内存 `Map`，只说明接口形状：重复创建得到同一码，`redirect: 'manual'` 看到 302 和 `location`。生产不能用递增码，也不能只放内存。创建接口按用户限流，并拒绝内网目标。
- 易错点：301。客户端会长期缓存，目标改了也跳不到新地址。
- 追问：码空间多大？随机 8 字节再 base64url 已经很大。冲突概率用生日界估计，冲突时再生成一次。

### Q2. 设计全局限流。

- 难度：高级
- 考察点：共享计数
- 参考答案：令牌桶有容量和补充速率。示例在单进程里用注入的时间证明 1 秒补充 1 个。多副本必须把扣减放到共享存储的原子操作里。键包含路由和用户或 IP。拒绝时 429，不在服务器里睡到令牌恢复。存储故障时事先选定“放行”或“拒绝”。
- 易错点：每个 Node 进程一个桶，就说已经全局限流。
- 追问：固定窗口的问题？窗口边界可以连续放进将近两倍配额。

### Q3. 设计上传。

- 难度：中级
- 考察点：流与替换
- 参考答案：`pipeline` 到同一文件系统的临时文件，累计字节，超限删除并 413。写完 `rename`。路径限制在根目录内。多实例把正式对象放到对象存储。校验内容放在落盘之后、对外提供之前。
- 易错点：`req.on('data')` 把所有块 `concat` 到一个数组里再写盘，内存仍是整个文件。
- 追问：断点续传？客户端带已有字节数，服务器校验已写入的长度和哈希后再追加。第一版可以不做，但要说明不做。

### Q4. 设计聊天室的多机部署。

- 难度：高级
- 考察点：连接不迁移
- 参考答案：每台机器保存自己接受的套接字。消息进入任意一台时，发布到总线，由持有该用户连接的机器写入套接字。cluster 轮询不适用于已经建立的长连接。断开时从集合移除。心跳超时就关掉，避免半开连接。历史消息进数据库，在线推送只负责在线的那一份。
- 易错点：用粘性会话代替总线，扩容和故障时用户会掉线且说不出消息去哪了。粘性会话可以要，但不能是唯一的投递机制。
- 追问：未读怎么做？写入数据库的收件箱，在线时推送，离线时下次拉取。

### Q5. 设计异步任务。

- 难度：高级
- 考察点：至少一次
- 参考答案：接口把任务写入队列并返回 id。工作者 `pull` 后在可见性窗口内执行，成功再 `ack`。崩溃则窗口过后再次可见。示例用数组演示了“未 ack 会再次取出”。执行必须幂等。失败计数达到上限进死信。接口和工作者分开扩容。用户查询读数据库。
- 易错点：承诺恰好一次。进程崩溃和网络重试下，对外说“至少一次，副作用幂等”。
- 追问：可见性太短会怎样？工作还在跑，任务已经交给第二个人，两个人一起写。窗口要长于 p99 执行时间，并在长任务上续约。

### Q6. Node 在系统里的位置？

- 难度：中级
- 考察点：不要把所有层都放进一个进程
- 参考答案：Node 适合 I/O 编排：HTTP、鉴权、拼装下游、推送。大计算放 Worker 或独立服务。状态放数据库。队列放专门的存储。TLS 和第一道体积限制可以放在反向代理。一个进程一种职责，才能按 D10 替换。
- 易错点：为了少一个组件，把队列、会话、文件都放进同一个进程内存。
- 追问：怎样判断该加副本而不是加 Worker？CPU 已经在多个请求的 JavaScript 上打满，加副本或 cluster。如果 CPU 很低，先看数据库和线程池。
