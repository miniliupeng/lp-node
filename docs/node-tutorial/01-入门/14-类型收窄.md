# 类型收窄

示例：`examples/A/14-guards.mjs`。运行时校验见[校验](../04-工程与系统设计/05-校验.md)。

TypeScript 的收窄发生在编译期。`node file.ts` 会把类型擦掉，所以收窄挡不住外部 JSON。这一章把编译期规则和运行时检查分开写。本仓库不安装 `tsc`，示例只演示运行时那一半。

## 是什么

收窄是控制流分析：在某个分支里，变量的类型比进入分支之前更小。

| 写法 | 编译器能收窄成 |
| --- | --- |
| `typeof x === 'string'` | `string` |
| `x === null` | 从联合里去掉 `null` |
| `Array.isArray(x)` | 数组 |
| `'name' in x` | 含有这个属性的那一支，仍要再查类型 |
| `x instanceof Date` | `Date`。跨上下文时运行时可能失败 |
| 自定义谓词 `x is User` | 你声明的那个类型 |

自定义谓词是返回 `arg is User` 的函数。它返回 true 时，编译器在后面把参数当成 `User`。运行时是否真的是 `User`，完全取决于函数体。写错了谓词，编译期仍然相信你。

可辨识联合是每支都有同一个字面量字段，例如 `kind: 'ok' | 'fail'`。`switch (result.kind)` 在编译期可以检查有没有写全。运行时没有类型，未知的 `kind` 必须在 `default` 里抛错。示例对 `later` 抛 `TypeError`。

## 为什么不要用 as

`as User` 不检查任何字段。JSON 缺 `name` 时，编译期当它有，运行时 `user.name` 是 `undefined`，再读属性就抛错。外部输入用运行时检查。检查通过之后，编译期再用谓词收窄。两边是同一套条件，而不是先断言再希望数据听话。

`unknown` 是外部数据的起点。`any` 会关掉后面的检查。函数参数若来自 HTTP，类型写成 `unknown`，再收窄。

## 运行时示例在断言什么

`isUser` 要求普通对象、`name` 是字符串、`age` 是整数。`{ name: 'ada', age: '36' }` 失败。`JSON.parse` 出来的对象即使带多余的 `role`，谓词也只回答「像不像用户」，不负责删字段。删字段是[校验](../04-工程与系统设计/05-校验.md)的白名单。

`handle` 只认识 `ok` 和 `fail`。这就是穷尽：编译期的 `never` 在运行时变成 `default` 里的抛错。没有 `tsc` 时，抛错是唯一还能执行的那一半。

## 本章问答

### 1. 类型守卫和类型断言差在哪？

**考点：** 一个有运行时条件，一个没有。

**回答：** 谓词的函数体要返回布尔值，调用处的收窄依赖这个返回值。`as` 没有条件。外部 JSON 用谓词或显式字段检查。`as` 只适合你刚从别处证明过、编译器跟不上的场合，并且要离证明很近。

### 2. 为什么 node file.ts 不能证明收窄是对的？

**考点：** 剥离不做检查。

**回答：** 22.23.4 把可擦除的类型去掉就执行。谓词写反了也会跑。`tsc --noEmit` 才看收窄有没有覆盖每一支。本仓库的示例用断言锁住运行时行为。

### 3. instanceof 在什么情况下会失误？

**考点：** 跨上下文的构造函数。

**回答：** 不同 Worker、不同 `vm`、不同次打包，`Date` 或自定义类可能不是同一个函数。`instanceof` 为 false。跨边界用字段结构，不用原型。

## 事故复盘

接口把 `req.body as User` 交给领域函数。调用方传了 `{ name: 1 }`，编译期不再说话，运行时 `name.trim` 抛错，变成 500 而不是 400。外部数据用 `unknown`，用和 `examples/A/14-guards.mjs` 一样的字段检查。

`instanceof` 用来识别另一个 Worker 传回来的错误对象，永远失败，于是重试了不该重试的错误。跨边界只认 `code`。

`switch` 没有 `default`。新加的 `kind` 在编译期若开了穷尽检查会报错，但 `node file.ts` 不做这个检查，运行时落到函数末尾返回 `undefined`。`default` 里抛错，让漏掉的分支变成明确失败。
