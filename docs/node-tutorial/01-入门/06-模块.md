# 模块

示例：`examples/A/06-modules.mjs`、`06-local.mjs`、`06-math.cjs`。循环依赖见[循环依赖](../03-运行时/12-循环依赖.md)。

| | ESM | CJS |
| --- | --- | --- |
| 扩展名 | `.mjs` | `.cjs` |
| 导出 | `export` | `module.exports` |
| 导入 | `import` | `require()` |
| 顶层 `await` | 可以 | 语法错误 |
| 目录 | `import.meta.dirname` | `__dirname` |

22.23.4 有 `import.meta.filename`。示例断言把它转回 `file:` URL 后等于 `import.meta.url`。

ESM 里加载 CJS：

```javascript
import { createRequire } from 'node:module';
const require = createRequire(import.meta.url);
const math = require('./06-math.cjs');
```

`createRequire` 的参数决定相对路径从哪解析。

同一版本上 `process.features.require_module === true`，CJS 的 `require()` 可以同步加载 ESM，得到模块命名空间。示例对 `06-local.mjs` 调用 `mul(2, 6)` 得到 12。被加载的 ESM 如果有顶层 `await`，同步 `require` 等不了，改用动态 `import()`。

同一个模块 URL 在一个进程里只评价一次。ESM 没有公开的 `require.cache` 可删。评价失败也会被记住，再次导入仍是那次拒绝。

内置模块写 `node:fs` 这种前缀，避免被同名包挡住。

ESM 导出是活绑定，读的是当前值。CJS 导出的是对象上的属性。循环依赖时两者差别很大，见[循环依赖](../03-运行时/12-循环依赖.md)。


## 是什么

一个文件被求值一次，结果按 URL 缓存。ESM 的导出是活绑定：读的是当前值，绑定本身只读。CJS 的 `module.exports` 是一个对象，别人拿到的是这个对象上的属性。属性若是原始值，读到的是当时取出来的值；属性若是对象，两边共享那个对象。

## 为什么「CJS 是值拷贝」这句话不完整

很多人背：CJS 导出拷贝，ESM 导出引用。对 `exports.n = 1` 后来又 `exports.n = 2` 这种重新赋值，已经 `const n = require(...).n` 的人看不到 2。但对 `exports.state = { n: 1 }` 然后改 `state.n`，另一边看得到，因为共享的是对象。循环依赖时两边的差别见[循环依赖](../03-运行时/12-循环依赖.md)。

## 加载规则

| | ESM | CJS |
| --- | --- | --- |
| 扩展名 | `.mjs`，或 `"type": "module"` 下的 `.js` | `.cjs`，或默认的 `.js` |
| 语法 | `import` / `export`，可以顶层 `await` | `require` / `module.exports`，顶层 `await` 是语法错误 |
| 求值时机 | 依赖先求值，绑定是静态的 | 执行到 `require` 才加载 |
| 目录 | `import.meta.dirname`、`import.meta.filename` | `__dirname`、`__filename` |
| 树摇 | 绑定是静态的，打包器能分析 | 动态 `require` 很难静态删除 |

22.23.4 上 `process.features.require_module === true`。CJS 可以同步 `require` 一个没有顶层 `await` 的 ESM，得到模块命名空间。有顶层 `await` 就必须 `import()`。ESM 里用 `createRequire(import.meta.url)` 加载旁边的 CJS，相对路径以这个 URL 为基准。

内置模块写成 `node:fs`。不写前缀时，同名的本地包会挡住内置模块。

求值失败也会被缓存。第二次导入同一 URL 得到的仍是第一次的拒绝。

## 本章问答

### 1. `require(esm)` 在 Node 22 能不能用？

**考点：** 同步加载的限制。

**回答：** 22.23.4 可以同步加载没有顶层 `await` 的 ESM。示例因此能调用 `mul(2, 6)`。被加载文件如果含顶层 `await`，同步 `require` 等不了，改用动态 `import()`。不要说「Node 永远不能 require ESM」，也不要说「所有 ESM 都能同步 require」。

### 2. ESM 和 CJS 的循环依赖为什么表现不同？

**考点：** 活绑定和暂时性死区。

**回答：** ESM 在初始化期间读取尚未赋值的 `const` 得到 `ReferenceError`。函数若在两边都初始化完之后才调用，就能读到已经赋好的绑定。CJS 在循环进行中只能看见当时已经挂到 `exports` 上的属性。见[循环依赖](../03-运行时/12-循环依赖.md)。

### 3. 为什么内置模块要写 `node:` 前缀？

**考点：** 解析顺序。

**回答：** 没有前缀时，Node 会先找 `node_modules` 里的同名包。依赖树里如果出现名为 `fs` 或 `util` 的包，不写前缀就会载入那个包。`node:fs` 只解析内置模块。

## 事故复盘

服务用 `require('./config')` 读到端口 `0`，因为循环依赖时 CJS 只看见已经赋上的属性，端口是后来才写上的。启动日志看起来正常，实际监听了随机行为。拆掉循环，或在两边都初始化完之后再读。ESM 若在初始化期间读 `const`，会直接 `ReferenceError`，见[循环依赖](../03-运行时/12-循环依赖.md)。

依赖里出现名为 `util` 的包之后，`require('util')` 载入了那个包，而不是内置模块。内置模块写成 `node:util`。

ESM 求值抛错被缓存。修完文件不重启进程，第二次 `import()` 仍是旧的拒绝。开发时新进程再跑，不要写一个循环去反复 import。

### 再答一题

**题目：** CJS 导出到底是拷贝还是引用？

**回答：** `exports` 是对象。对方拿到的是这个对象的引用。重新赋 `exports.n = 2` 不会更新对方已经读进局部变量的数字。改对象字段 `exports.state.n = 2` 两边都看得见。ESM 的导出名是活绑定，读的永远是当前值，绑定本身只读。
