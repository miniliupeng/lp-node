# 值与相等

示例：`examples/A/02-values.mjs`

原始值有 `undefined`、`null`、布尔、数字、`bigint`、字符串、`symbol`。对象包括普通对象、数组、函数、日期。`typeof null` 是 `"object"`，判断空值用 `value === null`。

普通数字是双精度。超过 `Number.MAX_SAFE_INTEGER`（约 9e15）的整数不能精确表示，主键和雪花 ID 用字符串或 `bigint`。

`Number('nope')` 是 `NaN`。`NaN === NaN` 为 `false`，`Object.is(NaN, NaN)` 为 `true`。`+0 === -0` 为 `true`，`Object.is(+0, -0)` 为 `false`。示例用 `Number('-0')` 构造负零，因为源码里的 `-0` 会被一些格式化工具印成 `0`。`1 / -0` 是 `-Infinity`。

`const alias = shared` 之后两边是同一个对象，改字段彼此可见。原始值赋值复制的是值。

`structuredClone` 能复制普通对象、数组、`Date`、`Map`、`Set`。它不复制函数，也不保留类的方法。示例里的 `Box` 克隆后是 `{ n: 3 }`，原型是 `Object.prototype`，`double` 消失。浅拷贝 `{ ...obj }` 只复制第一层。

字符串 `length` 统计 UTF-16 码元，不是 UTF-8 字节。`héllo` 在[字节与 Buffer](../02-进阶/01-字节与Buffer.md)里是 5 个码元、6 个字节。


## 是什么

JavaScript 的值分成原始值和新对象。原始值按值比较，对象按引用比较。相等有三套规则：`==`（会转换类型）、`===`（SameValueZero 的近亲，但不区分 `NaN` 和 `±0`）、`Object.is`（SameValue）。

## 为什么这会变成线上事故

主键用 `number` 存雪花 ID，超过 `Number.MAX_SAFE_INTEGER`（2^53-1）之后相邻整数无法区分，查出来的不是写入的那个 ID。用 `==` 比较端口和字符串 `"0"` 会通过。用 `x === NaN` 判断解析失败永远是 false。

## 数字、零和 NaN

普通数字是 IEEE-754 双精度。`0.1 + 0.2 !== 0.3`。钱用整数分，或者用十进制库，不要用二进制浮点做结账。

`Number('nope')` 是 `NaN`。`Number.isNaN` 只在值已经是 NaN 时为真。全局 `isNaN('nope')` 会先转换，得到 true，不要用它做校验。

`Object.is` 认为 `NaN` 等于 `NaN`，并区分 `+0` 与 `-0`。`===` 相反。`1 / -0` 是 `-Infinity`。示例用 `Number('-0')`，避免格式化工具把源码里的 `-0` 印成 `0`。`node:assert/strict` 的 `equal` 走 `Object.is`。

## 引用和复制

`const alias = shared` 之后两边是同一个对象。`structuredClone` 能复制普通对象、数组、`Date`、`Map`、`Set`、`ArrayBuffer`。它丢掉函数和方法，类实例变成普通对象。它不能克隆带函数的对象图，遇到会抛 `DataCloneError`。

`{ ...obj }` 和 `Object.assign` 只复制第一层。嵌套对象仍然共享。

## 本章问答

### 1. `==`、`===`、`Object.is` 怎么选？

**考点：** 三套相等。

**回答：** 业务代码用 `===`。需要把 `NaN` 当成相等，或区分正负零时用 `Object.is`。不要用 `==`，它会把 `''`、`0`、`false` 互相看成相等。断言库如果文档写的是 `Object.is`，`NaN` 会通过，这和 `===` 不同。

**易错：** 用 `JSON.stringify` 比较两个对象是否相等。键顺序和 `undefined` 都会让结果不可靠。

### 2. 为什么大整数不能放进 number？

**考点：** 安全整数范围。

**回答：** 超过 `Number.MAX_SAFE_INTEGER` 的整数不能精确表示。数据库主键、订单号用字符串或 `bigint`。`bigint` 不能和 `number` 直接运算，`JSON.stringify` 遇到 `bigint` 会抛 `TypeError`。

### 3. 克隆之后为什么方法没了？

**考点：** 结构化克隆的边界。

**回答：** `structuredClone` 复制的是数据，不是原型上的方法。示例里的 `Box` 克隆后只剩 `{ n: 3 }`。要保留行为，就传数据、在接收端重新构造类，而不是克隆实例。

## 事故复盘

订单号用 `number` 存在前端，再 `JSON.stringify` 发给 Node。超过 `2^53-1` 的整数在解析时已经变成另一个数，数据库查不到原订单，也不会抛错。契约改成字符串。需要运算再用 `bigint`，并单独处理它不能被 `JSON.stringify` 的事实。

`==` 把空字符串和 `0` 看成相等之后，折扣配置「未填」被当成 0 折，整单免费。比较配置用 `===` 或 `Object.is`，缺省用 `??`。

`structuredClone` 克隆了会话对象之后，方法没了，调用 `refresh()` 抛出「不是函数」。克隆只带走数据。需要行为时在接收端重新构造对象。

### 再答一题

**题目：** 断言库说两个 NaN 相等，业务代码里 `===` 却不相等。以哪个为准？

**回答：** 语言里的 `===` 认为 `NaN` 不等于 `NaN`。`node:assert/strict` 的 `equal` 用 `Object.is`，所以测试里的 `NaN` 会通过。业务判断解析失败要用 `Number.isNaN`，不要用 `===`，也不要假设测试库的相等就是语言的 `===`。
