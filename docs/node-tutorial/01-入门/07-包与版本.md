# 包与版本范围

示例：`examples/A/07-semver.mjs`。它只实现 major ≥ 1 的 `^` 和 `~`，遇到 `^0.2.3` 会抛错，因为 npm 对 0.x 的插入符只允许补丁升级。

`MAJOR.MINOR.PATCH`：补丁是修复，次版本是兼容的新能力，主版本可以不兼容。

在 major ≥ 1 时：

- `1.2.3` 只接受这个版本
- `~1.2.3` 接受 ≥1.2.3 且 <1.3.0
- `^1.2.3` 接受 ≥1.2.3 且 <2.0.0

示例断言 `^1.2.3` 接受 `1.9.0`，拒绝 `2.0.0` 和 `1.2.2`。

`package.json` 里的范围在下一次安装时可能解出新补丁。锁文件记下这一次的具体版本和完整性校验。应用仓库提交锁文件。

`dependencies` 是运行所需，`devDependencies` 是测试和类型检查所需。`"private": true` 防止误发布。`exports` 声明公共入口，包外不能再随意引用未导出的深路径。

安装目录 `node_modules` 不提交。本教程的示例不安装任何包。


## 是什么

版本号 `MAJOR.MINOR.PATCH` 是给人不给机器的约定：补丁修缺陷，次版本加兼容能力，主版本可以不兼容。包管理器把范围解成具体版本，锁文件把这一次的选择钉死。

## 范围不要背错

主版本 ≥ 1 时：

| 范围 | 接受 |
| --- | --- |
| `1.2.3` | 只有这个版本 |
| `~1.2.3` | ≥1.2.3 且 <1.3.0 |
| `^1.2.3` | ≥1.2.3 且 <2.0.0 |

npm 对 `^0.2.3` 只允许补丁升级，因为 0.x 的次版本就可能不兼容。示例 `examples/A/07-semver.mjs` 对 `^0.x` 直接抛错，避免把 1.x 的规则套上去。

`package.json` 里的范围在下一次安装时可能解出新补丁。应用仓库提交锁文件。库仓库通常不提交锁文件，由使用方锁定。

## 依赖会怎样被装进磁盘

npm 和 Yarn v1 把依赖提升到顶层 `node_modules`，于是你可以 `import` 一个自己没声明的包。这叫幽灵依赖。上游不再依赖它时，你的代码在一台干净安装上失败。

pnpm 把每个版本的包内容放进全局的内容寻址存储，一份内容只存一次。项目里的文件通过硬链接指回这个存储，顶层 `node_modules` 里只有你直接声明的依赖的符号链接，真实文件在 `.pnpm` 下。没写进 `package.json` 的包解析不到。`pnpm install --frozen-lockfile` 在锁文件和清单不一致时失败，CI 用它挡住「本地能跑、流水线装出另一套」。

本仓库的示例不安装依赖，也没有锁文件。上面这段是工程事实，不是这一份教程的运行步骤。Node 22 可以带 Corepack，但是否已经启用要看 `corepack --version`，不要把 pnpm 说成 Node 的内置包管理器。

`dependencies` 是运行所需，`devDependencies` 是测试和类型检查所需。`"private": true` 防止误发布。`exports` 声明公共入口，包外不能再引用未导出的深路径。

## 本章问答

### 1. 幽灵依赖是什么，pnpm 怎么挡住？

**考点：** 提升和符号链接。

**回答：** npm 扁平化之后，子依赖出现在顶层，业务代码可以引用自己没声明的包。pnpm 的顶层只放直接依赖的符号链接，物理文件在内容寻址存储和 `.pnpm` 里，通过硬链接共享，不按项目再复制一份。没有声明的名字解析失败。

**易错：** 说 pnpm 只是「更快的 npm」，不提隔离。

### 2. `^1.2.3` 和 `^0.2.3` 为什么不能用同一句话解释？

**考点：** 0.x 的插入符。

**回答：** `^1.2.3` 接受到下一个主版本之前。`^0.2.3` 在 npm 里只接受补丁，不接受 `0.3.0`。示例因此拒绝按 1.x 的规则解释 0.x。

### 3. 为什么应用要提交锁文件？

**考点：** 可重复安装。

**回答：** 范围每次安装都可能选出新的补丁。锁文件记下具体版本和完整性校验。CI 用 `--frozen-lockfile`，清单和锁不一致就失败，而不是悄悄装出另一套。

## 事故复盘

应用没提交锁文件，CI 在发版当天装到了一个补丁，补丁里的默认导出改了名字，构建通过、运行时崩溃。应用仓库提交锁文件，CI 使用冻结安装。范围 `^1.2.3` 允许的是兼容范围内的新版本，不是「永远停留在 1.2.3」。

有人把 `^0.2.3` 理解成可以升到 `0.9.0`。npm 对 0.x 的插入符只允许补丁。示例因此对 `^0.x` 抛错，避免用 1.x 的口诀解释它。

幽灵依赖：业务 `import` 了自己没声明的包，因为 npm 把它提升到了顶层。上游去掉这个依赖后，干净安装失败。pnpm 的顶层只放直接依赖的符号链接。本仓库示例不安装包，这条是给真正的服务仓库的。

### 再答一题

**题目：** `exports` 字段解决什么问题？

**回答：** 它声明包的公共入口。没有它时，调用方可以引用包内部的深路径，你一重构就弄坏所有调用方。有了它，没导出的路径解析失败。这和运行时的 `export` 语法不是同一个词，讲的时候要说明是 `package.json` 的入口表。
