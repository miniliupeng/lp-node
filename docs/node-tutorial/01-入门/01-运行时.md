# 运行时与第一个程序

示例：`examples/A/01-hello.mjs`

Node.js 用来执行 JavaScript，并提供文件、网络、进程和加密这些宿主能力。浏览器里的 `document` 在这里不存在。

一个进程里主要有三层：

1. **V8** 执行 JavaScript，管理堆。
2. **libuv** 提供事件循环和线程池。
3. **Node 绑定** 把 `fs`、`http`、`crypto` 接到上面两层。

主线程同一时刻只跑一段 JavaScript。`await` 让出的是调用栈。文件和慢哈希会把阻塞工作交给 libuv 线程池，默认 4 个线程。这在[线程池与 DNS](../03-运行时/05-线程池与DNS.md)用实验说明。

```bash
node -v
node examples/A/01-hello.mjs
```

脚本打印 `process.version`、V8、libuv、OpenSSL，并断言主版本至少 22、LTS 代号是 `Jod`。这是 Node 22 的代号。Node 26 的代号是 Lithium，跑这个断言会失败，因为教程契约就是 22.23。

不带文件参数时进入 REPL。REPL 的 `this` 和模块规则与正式文件不同，能保留的程序写成文件。

`process.argv[0]` 是 node 二进制，`argv[1]` 是脚本路径，之后才是你的参数，类型都是字符串。`process.execPath` 是当前这个二进制，子进程应使用它，避免 PATH 上另一个 node。

主模块跑完且没有未完成的句柄（服务器、未 `unref` 的定时器、打开的套接字）时，进程以码 0 退出。

`.mjs` 一定按 ESM 执行。`.cjs` 一定按 CommonJS。`.js` 取决于最近的 `package.json` 是否 `"type": "module"`。本教程用扩展名把种类写死，所以没有自己的 `package.json` 也能跑。


## 是什么

Node.js 进程 = **V8 隔离实例** + **libuv 事件循环** + 一层 C++ 绑定。用户写的 JavaScript 在主线程上跑。网络套接字的就绪通知来自操作系统的多路复用（Linux 上是 epoll，macOS 上是 kqueue，Windows 上是 IOCP），这一层不为每个连接分配一条操作系统线程。文件、DNS 的 `lookup`、`pbkdf2` 这类会阻塞的调用，在 22.23.4 上交给 libuv 线程池，默认 4 条。

「单线程」只描述 JavaScript 的执行。整个进程不是一个线程。`worker_threads` 再开隔离实例，`cluster` 再开进程，见[进程结构](../03-运行时/01-进程结构.md)。

## 为什么需要分清这三层

把 CPU 重的同步循环放进 HTTP 处理函数，所有连接一起停，因为它们共用这一条 JavaScript 线程。把「Node 能扛高并发」理解成「什么计算都不会堵」，上线后事件循环延迟会先爆。高并发指的是大量连接在等 I/O，而不是大量请求同时做重计算。

## 进程里要会读的字段

| 字段 | 含义 |
| --- | --- |
| `process.version` | 例如 `v22.23.4` |
| `process.versions` | V8、libuv、OpenSSL、undici 各自的版本 |
| `process.release.lts` | 22 是 `Jod`。26 是 Lithium，本教程的示例会因此失败 |
| `process.pid` / `process.ppid` | 当前进程和父进程 |
| `process.execPath` | 这一次启动用的 node 二进制。子进程用它，不用 `node` 这个名字 |
| `process.argv` | `[二进制, 脚本, ...用户参数]`，全是字符串 |
| `process.execArgv` | 给 node 自己的参数，例如 `--permission`，不含脚本名 |
| `process.memoryUsage()` | `rss`、`heapUsed`、`heapTotal`、`arrayBuffers` |
| `process.cpuUsage()` | 用户态和内核态 CPU 时间，单位微秒 |

示例 `examples/A/01-hello.mjs` 打印版本并断言主版本 ≥ 22 且 LTS 代号是 Jod。它不断言内存数字，因为堆大小随启动变化。

## 进程什么时候退出

主模块的同步代码跑完之后，只要还存在被引用的句柄，进程就继续等。服务器、未 `unref` 的定时器、打开的套接字都算。`timer.unref()` 让这个定时器不阻止退出，见[定时器](../02-进阶/08-定时器.md)。`server.close()` 只是停止接新连接，见[优雅退出](../04-工程与系统设计/10-优雅退出.md)。

REPL 里的 `this`、未写扩展名的模块解析，和正式文件不一样。能留下的程序写成 `.mjs` 或 `.cjs`。

## 本章问答

### 1. Node 是单线程，为什么还能接很多连接？

**考点：** JavaScript 线程和 I/O 线程不是一回事。

**回答：**

1. JavaScript 和事件循环在主线程上。同一时刻只执行一段用户代码。
2. 网络连接的可读可写由 epoll / kqueue / IOCP 通知，不按连接数创建操作系统线程。
3. 22.23.4 上，异步文件和慢哈希走默认 4 线程的线程池。池子被占满时，后来的文件读取会排队，见[线程池与 DNS](../03-运行时/05-线程池与DNS.md)。
4. 适合的是大量连接、每段 JavaScript 很短的服务。同步压缩、同步 JSON 大对象、死循环都会把所有连接拖住。

**易错：** 说「进程里只有一个线程」。`ps -M` 或调试器里能看到 libuv 的工作线程。

### 2. `argv` 和 `execArgv` 有什么差别？

**考点：** 参数落在谁身上。

**回答：** `execArgv` 是 node 的开关。`argv[0]` 是二进制，`argv[1]` 是脚本，后面才是业务参数，而且都是字符串。端口要自己 `Number` 再检查整数。子进程若写 `'node'`，可能跑到 PATH 上另一个版本，应传 `process.execPath`。

**易错：** 把 `--inspect` 当成 `argv` 里的业务参数。

### 3. 主模块已经 return 了，进程为什么还不退出？

**考点：** 句柄保持事件循环。

**回答：** 还有服务器在 listen、定时器没 `unref`、套接字没关、或者拒绝还没被处理。先查这些句柄，而不是再调一次 `process.exit()`。后者会跳过收尾。

## 事故复盘

一台机器从 Node 20 升到 22 之后，健康检查仍是绿的，但日志里的 OpenSSL 和 undici 版本变了。接口行为没变，密码套件和 `fetch` 的连接池行为可能变。上线清单要写明 `process.version`、`process.versions.openssl`、`process.versions.undici`，而不是只写「Node 22」。

另一个常见事故是用 `process.exit(1)` 处理配置错误。监督进程看到非 0 退出会重启，但正在写的响应被掐断，负载均衡还没把实例摘掉。配置失败应发生在 `listen` 之前；接流量之后的退出走[优雅退出](../04-工程与系统设计/10-优雅退出.md)。

REPL 里试出来的 `this` 和未保存的表达式不要贴进服务。`.mjs` 是严格模式，拆出来的方法调用会因 `this` 为 `undefined` 抛错。把能留下的代码放进文件，用 `examples/A/01-hello.mjs` 的方式断言版本，而不是把 `console.log` 当测试。

### 再答一题

**题目：** 为什么高并发服务仍会被一个请求拖死？

**回答：** 网络连接的就绪不占 JavaScript 线程，但每个回调仍在主线程上跑。一个请求里的同步循环、`readFileSync` 或同步压缩会挡住所有连接。先用 `performance.now` 量这段同步时间，再决定要不要挪到 Worker。线程池默认只有 4 条，它解决不了主线程上的 JavaScript。
