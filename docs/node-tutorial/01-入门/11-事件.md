# 事件

示例：`examples/A/11-events.mjs`

`EventEmitter` 的 `emit` 会按注册顺序同步调用监听器。`on` 一直留着，`once` 在第一次之后移除。示例对 `tick` 得到 `[1, 'once', 2]`。

`events.once(emitter, 'done')` 返回 Promise，等到下一次该事件，参数以数组给出。

`'error'` 没有监听器时，`emit('error', err)` 会把 `err` 抛出。示例用子进程跑了这段，进程非 0 退出，stderr 含 `boom`。服务器、套接字和流至少要登记 `error`，哪怕只是记日志。

同一事件默认超过 10 个监听器会警告。这通常是每次请求 `on`、却从不 `off`。`off` 需要当初注册的那个函数引用，临时箭头函数摘不掉。请求结束或信号中止时移除监听器。

流的错误更适合交给 `stream.promises.pipeline`，见[流与背压](../02-进阶/02-流与背压.md)。


## 是什么

`EventEmitter` 按注册顺序同步调用监听器。`on` 一直留着，`once` 在第一次之后移除。`emit` 的返回值表示当时有没有监听器。

## 为什么 error 事件特殊

普通事件没有监听器时，`emit` 什么也不做。`'error'` 没有监听器时，`emit('error', err)` 把 `err` 抛出。示例用子进程跑了这段，进程非 0 退出，stderr 含 `boom`。服务器、套接字和流至少要登记 `error`，哪怕只是记日志再关闭。

同一事件默认超过 10 个监听器会警告。这通常是每次请求 `on`、却从不 `off`。`off` 需要当初注册的那个函数引用。临时箭头函数摘不掉，因为前后不是同一个函数。

`events.once(emitter, 'done')` 返回 Promise。如果先等到 `error`，这个 Promise 拒绝，避免一直挂着。

流的错误更适合交给 `stream.promises.pipeline`，见[流与背压](../02-进阶/02-流与背压.md)。

## 本章问答

### 1. 为什么要单独监听 error？

**考点：** 没有监听器时的默认行为。

**回答：** 其他事件没人听就丢掉。`error` 没人听会抛异常，请求路径上就是进程崩溃。监听器里记录 `code` 和 `cause`，不要再把同一个错误无监听地 `emit` 出去。

### 2. 怎么保证监听器会被摘掉？

**考点：** 函数引用。

**回答：** 把监听器存成具名函数，在请求结束、`close` 或 `AbortSignal` 时 `off`。`once` 适合只等一次的事件。超过 10 个的警告是泄漏信号，不是让你把上限调大就结束。

### 3. emit 是异步的吗？

**考点：** 同步调用。

**回答：** 不是。`emit` 按顺序同步调用当前的监听器。监听器里再 `emit` 同一个事件会重入。不要在监听器里做长时间同步计算。

## 事故复盘

每个请求 `emitter.on('data', () => ...)` 使用新的箭头函数，请求结束没有 `off`。超过 10 个监听器开始警告，内存随请求上涨。把函数存下来，在 `close` 或 `abort` 时摘掉，或改用 `once`。

套接字没有 `error` 监听器。对端重置连接时，`emit('error')` 变成未捕获异常，进程退出。服务器、流和套接字都要有 `error` 监听器。

在监听器里同步递归 `emit` 同一事件，栈溢出。需要再发事件时放到 `nextTick` 或 `setImmediate`，并限制次数。
