# 断言与调试

示例：`examples/A/13-assert.mjs`，测试文件 `examples/B/11-sample.test.mjs`。

`node:assert/strict` 在条件失败时抛 `AssertionError`。教程脚本以此区分成功和失败，成功才打印 `PASS`。

`assert.equal` 使用 `Object.is`，所以它认为 `NaN` 等于 `NaN`，并区分 `+0` 与 `-0`。这和 `===` 不同。`deepEqual` 比较结构。两个分别写成的 `{ a: 1 }` 用 `equal` 比较会失败，因为不是同一个引用。

同步抛错用 `assert.throws`，异步拒绝用 `await assert.rejects`。统一用 `node:assert/strict`，避免宽松比较把 `1` 和 `'1'` 当成相等。

堆栈从你的文件那一帧读起。`node:internal` 那几帧是运行时自己的。

```bash
node --inspect-brk examples/A/12-http.mjs
```

进程会在第一行暂停，检查器默认端口 9229。不要对公网开放这个端口。

`node --test examples/B/11-sample.test.mjs` 运行 `node:test`。`mock.fn` 记录调用参数。`mock.timers` 在 22.23.4 仍打印实验警告，防抖示例改为注入 `{ set, clear }`，见[手写题](../05-面试题库/11-手写题.md)。覆盖率开关 `--experimental-test-coverage` 名字里仍带 experimental。

异步测试忘了 `await` 时，用例可能在断言之前就被标成通过。


## 是什么

`node:assert/strict` 在条件失败时抛 `AssertionError`，进程因此非 0 退出。教程用它区分「跑完了」和「跑对了」。`node:test` 在 Node 22 是稳定的测试运行器。

## 断言的比较规则

`assert.equal` 使用 `Object.is`，所以 `NaN` 等于 `NaN`，并区分 `+0` 与 `-0`。这和 `===` 不同。`deepEqual` 比较结构。两个分别写成的 `{ a: 1 }` 用 `equal` 会失败，因为不是同一个引用。

同步抛错用 `assert.throws`，异步拒绝用 `await assert.rejects`。统一用 `node:assert/strict`。宽松的 `assert` 会把 `1` 和 `'1'` 看成相等。

## 本章问答

### 1. 为什么教程不用 Jest？

**考点：** 工具是否被当前运行时自带。

**回答：** `node:test` 和 `node:assert/strict` 随 Node 22 提供，示例零依赖就能跑。Jest 还要处理 ESM、转换和自己的定时器模拟。本仓库不安装它。需要模拟时间时，把 `set` / `clear` 当参数注入。

### 2. assert.equal 和 === 有哪一点不同？

**考点：** `Object.is`。

**回答：** `equal` 认为两个 `NaN` 相等，并认为 `+0` 和 `-0` 不相等。`===` 对这两对的结论相反。深比较用 `deepEqual`，不要用 `JSON.stringify` 当断言。

### 3. 怎样调试一个一直不退出的脚本？

**考点：** 句柄，而不是断点数量。

**回答：** 先看有没有服务器、定时器、套接字没关。`node --inspect-brk` 在第一行暂停，用检查器看调用栈。不要在生产机器上把 9229 暴露到公网。

## 事故复盘

异步测试写成 `test('x', () => { assert.rejects(promise) })`，没有返回这个 Promise。运行器先标通过，随后出现未处理拒绝，进程退出码和报告对不上。测试函数改成 `async` 并 `await`。

用 `mock.timers` 写的防抖测试在 22.23.4 上打印实验警告，升级小版本后假时钟的语义可能变。示例改成注入 `{ set, clear }`。

`node --inspect-brk` 忘了关掉就部署，9229 对内网开放。检查器只在本机排错时开，不要进生产启动命令。
