# 大厂高频面试题精讲 (01-primitive-and-reference)

---

### Q1: JavaScript 中有哪些基本（原始）类型？它们与引用类型在底层内存分配上有何本质区别？

#### 🎯 面试官考点
- JS 语言底层的 7 大原始类型与 V8 内存分区（栈 Stack vs 堆 Heap）。

#### 💡 满分回答模板
1. **7 大原始类型**：`number`, `string`, `boolean`, `null`, `undefined`, `symbol`, `bigint`。
2. **底层内存分配模型**：
   - **原始类型**：占据固定大小的内存空间，通常直接在**调用栈（Stack）**中分配。操作时是直接操作保存在变量中的实际值，赋值或传参时进行的是**值拷贝（Pass-by-Value）**，两者互不影响。
   - **引用类型（Object/Array/Function等）**：大小不固定（可能动态扩容），实际数据存储在**堆内存（Heap）**中。栈内存中只保存一个指向该堆内存起始物理地址的**指针（Reference）**。
   - **参数传递本质**：JS 中一切皆是按值传递。当传递对象时，传递的是“该对象的指针值的拷贝”，因此函数内如果直接修改对象属性，外部引用的同一个堆内存数据会被同步篡改。

### Q2: 为什么在生产环境中绝不应该使用 `JSON.parse(JSON.stringify(obj))` 进行深拷贝？它有哪些致命缺陷？

#### 🎯 面试官考点
- 考察对 JSON 序列化规范边界、特殊数据类型丢失与性能损耗的认知。

#### 💡 满分回答模板
1. **循环引用直接爆栈**：如果对象存在循环引用（如 `a.self = a`），会直接抛出 `TypeError: Converting circular structure to JSON` 导致进程崩溃。
2. **特殊数据类型直接丢失或篡改**：
   - **`undefined` / `Function` / `Symbol`**：作为对象属性时会直接被**静默丢弃（忽略）**；作为数组项时会被强制转换为 `null`。
   - **`Date` 对象**：会被错误转变为 ISO 字符串，拷贝回来后变成了普通 `string`，失去了日期对象的原型方法。
   - **`RegExp` / `Error` 对象**：会被直接转为空对象 `{}`。
   - **`Map` / `Set`**：会被直接转为 `{}`，原本的键值对全部丢失。
   - **`NaN` / `Infinity`**：会被序列化强制变成 `null`。
3. **性能低下**：经过先转字符串再重新词法解析，内存与 CPU 双重浪费。

### Q3: 现代原生 `structuredClone()` 的底层优势是什么？它不支持拷贝哪些对象？

#### 🎯 面试官考点
- 现代 Web / Node.js 标准演进与结构化克隆算法（The structured clone algorithm）。

#### 💡 满分回答模板
1. **核心优势**：
   - **天然支持循环引用**：能够自动识别并保留对象图中的循环引用关系，不会爆栈；
   - **广泛支持复杂内置对象**：原生支持深拷贝 `Date`, `RegExp`, `Map`, `Set`, `ArrayBuffer`, `TypedArray` 等；
   - **由 C++ 引擎底层实现**：性能和内存利用率显著优于任何手写 JS 递归或 JSON 序列化。
2. **不支持的边界（会抛出 `DataCloneError`）**：
   - **`Function`**：函数（闭包）不能被克隆；
   - **DOM 节点**：在浏览器环境下不能克隆真实的 DOM 元素；
   - **属性描述符与原型链**：不保留 `getter`/`setter`、不可枚举属性，也不会保留自定义类（Class）的原型链继承关系（克隆后会退化为普通纯对象）。
