# 大厂高频面试题精讲 (01-fs-and-path-basics)

---

### Q1: `path.join()` 与 `path.resolve()` 的根本区别是什么？

#### 🎯 面试官考点
- 路径规范化（Normalization）与绝对路径解析基准。

#### 💡 满分回答模板
1. **`path.join([...paths])`：纯粹的相对路径字符串拼接**
   - 它的逻辑很简单：把传入的所有路径片段用平台特定的分隔符（Windows 为 `\`，POSIX 为 `/`）连接起来，并自动规范化（解析其中的 `.` 和 `..`）。
   - 如果没有传入根路径 `/`，返回的结果依然是相对路径（例如 `path.join('a', 'b')` 返回 `'a/b'`）。
2. **`path.resolve([...paths])`：从右向左解析，始终返回绝对路径**
   - 相当于在终端里从当前工作目录（`process.cwd()`）出发，依次执行 `cd` 操作。
   - 它从后往前逐个处理路径片段，直到拼接出一个绝对路径为止。如果处理完所有参数仍未形成绝对路径，它会强制加上当前工作目录的绝对前缀。
   - **典型坑点**：如果遇到带 `/` 开头的绝对路径参数，会直接重置当前路径基准（例如 `path.resolve('/a', '/b')` 返回 `'/b'` 而非 `'/a/b'`）。

### Q2: 什么是文件系统的“原子写入（Atomic Write）”？为什么写入重要配置时严禁直接使用 `fs.writeFile`？

#### 🎯 面试官考点
- 掉电安全、半写损坏态（Torn Writes）与操作系统 POSIX 语义。

#### 💡 满分回答模板
1. **直接调用 `fs.writeFile` 的致命风险**：
   - 当调用 `fs.writeFile` 时，底层通常会先将目标文件截断（Truncate）为 0 字节，然后分批次将数据块从内存刷入磁盘。
   - 如果在这个几毫秒~几秒的写入过程中，发生**服务器宕机、断电、K8s 容器被强杀（OOM / SIGKILL）**，目标文件就会停留在“半成品状态”（要么是 0 字节空文件，要么是损坏的残缺 JSON）。下次服务重启时读取就会抛出 JSON Parse 语法错误，导致服务永久起不来！
2. **原子写入的解法（Write-Rename 模式）**：
   - **步骤**：先把新数据完整写入同目录下的临时文件（如 `config.json.tmp.123`），确认完全写入并 `fsync` 刷盘无误后，再调用 `fs.rename` 进行替换。
   - **底层保障**：在 POSIX 文件系统标准中，同一文件系统内的 `rename` 系统调用是由内核保障的**原子操作（Atomic Operation）**。在任何时刻，文件要么是完整的旧版本，要么是完整的新版本，绝不可能出现中间半写的损坏态。

### Q3: 为什么在 Node.js 服务端高并发业务代码中严禁使用 `fs.readFileSync`？

#### 🎯 面试官考点
- 单线程事件循环模型阻塞的链式反应（Cascading Failure）。

#### 💡 满分回答模板
1. **主线程被物理冻结**：
   - Node.js 的 JavaScript 代码和事件循环主线程是单线程的。`readFileSync` 是一个同步系统调用（C++ 层的 `read`），在内核完成磁盘读取并将数据拷贝回 V8 堆内存之前，**整个 JavaScript 主执行线程会被物理级挂起阻塞**。
2. **引发雪崩灾难**：
   - 如果读取一个 50MB 的日志文件耗时 100 毫秒，在这 100 毫秒内：
     - 事件循环完全停摆；
     - 所有在线用户的 HTTP 请求无法建立连接；
     - 所有的定时器、微任务全部被挂起；
     - 上游负载均衡器（Nginx / K8s Ingress）可能会认为服务无响应而触发健康检查失败并踢出节点，导致集群整体雪崩。
3. **唯一例外允许场景**：
   - 仅在**应用启动阶段（Application Bootstrap）**读取一次性的本地配置文件或证书时，为了保证配置先于端口监听就绪，可以谨慎使用同步 API；但服务一旦开始对外 listen 监听流量，所有代码必须全部使用 `fs/promises` 异步非阻塞操作。
