# 大厂高频面试题精讲 (03-worker-threads-cpu-bound)

---

### Q1: `worker_threads`（工作线程）与 `cluster`（工作进程）有什么本质区别？在实际业务中如何权衡选型？

#### 🎯 面试官考点
- 多进程 vs 多线程在内存开销、故障隔离性与通信效率上的根本权衡。

#### 💡 满分回答模板
| 维度 | `cluster` (多进程) | `worker_threads` (多线程) |
| :--- | :--- | :--- |
| **物理实体** | **独立的 OS 进程（PID 不同）** | **同一进程内的多个 OS 线程** |
| **内存开销** | **较高**（每个进程独立占据完整的 Node 运行时和内存基线，约 30MB+） | **极低**（共享进程资源基线，线程创建与上下文切换轻量） |
| **故障隔离** | **强隔离**（某个 Worker 崩溃/内存溢出，不影响其他进程和主进程） | **弱隔离**（某个线程若触发底层段错误 Segmentation Fault，**会导致整个进程直接崩溃**） |
| **数据共享** | 必须经过跨进程序列化 IPC，无法直接共享内存 | 原生支持 **`SharedArrayBuffer` 零拷贝共享内存** |

- **架构选型原则**：
  - **I/O 密集型 Web 服务横向扩容**（利用多核 CPU 监听端口处理更多 QPS）：**无脑首选 `cluster`**，天然进程隔离，稳定性极强；
  - **CPU 密集型复杂计算**（图像处理、加密解密、音视频转码、大规模矩阵运算）：**首选 `worker_threads`**，不阻塞主线程，且线程间数据交换开销极小。

### Q2: 主线程与 Worker 线程之间传递数据有哪些方式？如何避免传递大数据时的序列化性能瓶颈？

#### 🎯 面试官考点
- 结构化克隆算法（Structured Clone）、可转移对象（Transferable Objects）与零拷贝优化。

#### 💡 满分回答模板
1. **默认方式：结构化克隆（值拷贝）**：
   - 默认调用 `worker.postMessage(data)` 时，数据会通过底层的结构化克隆算法进行深拷贝。如果传递一个 100MB 的对象，克隆过程会产生巨大的 CPU 消耗和瞬时内存翻倍。
2. **零拷贝优化手段 A：可转移对象（Transferable Objects）**：
   - 如果传递的是二进制 `ArrayBuffer`，可以在 postMessage 的第二个参数中将其所有权转移：
     ```typescript
     const buffer = new ArrayBuffer(1024 * 1024 * 50); // 50MB
     worker.postMessage(buffer, [buffer]); // 转移所有权
     ```
   - **效果**：主线程瞬间将底层内存指针切给子线程，耗时 **0 毫秒**；但主线程持有的原 buffer 会立即被清空剥离（变成不可读），避免并发竞争。
3. **零拷贝优化手段 B：共享内存（`SharedArrayBuffer`）**：
   - 两端直接映射同一块物理内存，读写全在本地，完全无需任何拷贝。

### Q3: 什么是 `SharedArrayBuffer` 与 `Atomics`？在 Node.js 多线程中为什么使用共享内存必须配合原子操作？

#### 🎯 面试官考点
- 内存并发数据竞争（Data Race）、指令重排与操作系统的原子指令（Atomic Primitives）。

#### 💡 满分回答模板
1. **`SharedArrayBuffer` 的作用**：
   - 一种特殊的二进制缓冲区，允许多个 Worker 线程同时直接读写同一块物理内存，实现终极的纳秒级零拷贝通信。
2. **为什么必须配合 `Atomics`（原子操作对象）**：
   - **竞态条件（Race Condition）**：在底层，即使简单的自增操作 `sharedArray[0]++` 也包含了三步机器指令：读取内存 -> CPU 累加 -> 写回内存。如果两个线程同时执行，可能会互相覆盖，导致最终结果错误。
   - **`Atomics` 的安全保障**：JavaScript 提供了全局的 `Atomics` 静态对象（如 `Atomics.add()`, `Atomics.load()`, `Atomics.wait()`），它直接调用 CPU 底层的**总线锁或硬件级原子指令**：
     1. 保证“读-改-写”作为一个不可分割的原子操作完成，杜绝数据竞争；
     2. 提供内存屏障（Memory Barrier），防止 CPU 乱序执行优化导致的时序不一致问题。
